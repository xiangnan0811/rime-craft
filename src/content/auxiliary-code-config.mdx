# 辅助码配置

辅助码（Auxiliary Code）是解决拼音重码问题的利器——在拼音之后追加 1-2 个字形码，可将数十个同音候选词精确缩减到 1-3 个。rime-ice、万象等方案通过 `script_translator` 原生支持辅助码，无需额外插件。

## 这是什么

拼音输入法最大的痛点是**重码**。输入 `shi` 会出现「是、时、事、式、市、师、诗……」几十个候选，需要频繁翻页。辅助码在拼音之后补充**字形维度**的信息，形成「音形结合」的输入方式：拼音定音，形码定形。

辅助码**不替代**拼音，而是在需要时追加额外编码来精确筛选。日常打词组时不需要辅助码（词组本身重码少），只有在打单字或遇到高重码时才会用到。

:::tip
辅助码是渐进式功能——你可以只对「的地得」「他她它」等最常见的重码字记住辅助码，已经能显著减少翻页次数。不需要一次记住所有字。
:::

## 快速上手

<StepGuide>
  <Step title="选择辅助码方案">
    在编辑器「辅助码配置」模块找到「辅助码方案」下拉框。初次尝试推荐选择**简单鹤**（simple_he）或**自然码**（zrm）——规则较简单，学习成本低。如果你已经使用小鹤双拼，鹤形（hexing）是自然延伸。
  </Step>
  <Step title="设置触发方式">
    找到「引导方式」选项，选择你偏好的辅助码触发模式：
    - **反引号引导**（backtick）：先输入拼音，遇到重码时按 `` ` `` 再输入辅助码，最容易上手
    - **间接辅助码**（indirect）：用 `;` 分隔拼音和辅助码，如 `ni;h`，视觉清晰
    - **直接辅助码**（direct）：拼音与辅助码直接相连，如 `nih`，效率最高但需熟练

    新手建议从「反引号引导」开始。
  </Step>
  <Step title="开启辅助码提示">
    打开「辅助码提示」开关，并将「提示长度」设为 `1`（只对单字显示）。这样候选词旁会显示对应的辅助码，方便边打字边学习记忆。
  </Step>
  <Step title="保存并重新部署">
    点击编辑器右上角「保存」，然后触发「重新部署」。修改辅助码配置后必须重新部署才能生效。
  </Step>
  <Step title="测试效果">
    在任意输入框测试：输入 `ta`，观察候选词「他/她/它」各自旁边显示的辅助码提示。然后在拼音后追加对应辅助码，验证候选词精确到目标字。
  </Step>
</StepGuide>

## 配置项详解

### 辅助码方案

内置 8 种辅助码系统，每种基于不同的字形拆分逻辑：

| 方案 | 值 | 编码依据 | 学习成本 | 典型用户 |
|------|----|---------|---------|---------|
| 墨奇码 | `moqi` | 字形拆分（部首+结构） | 中等 | 万象推荐默认，资料最丰富 |
| 鹤形 | `hexing` | 字根（类五笔，鹤形规则） | 中高 | 小鹤双拼用户的自然延伸 |
| 自然码辅助 | `zrm` | 部首+笔画 | 中等 | 自然码双拼用户配套使用 |
| 虎码辅助 | `tiger` | 字根（虎码规则） | 中高 | 追求极低重码率的进阶用户 |
| 五笔 | `wubi` | 五笔字根 | 高 | 已有五笔基础，零额外学习成本 |
| 仓颉 | `cangjie` | 仓颉字根 | 高 | 已有仓颉基础的用户 |
| 简单鹤 | `simple_he` | 鹤形简化版 | 低 | 辅助码入门首选，规则最简单 |
| 汉心码 | `hanxin` | 笔画顺序 | 低 | 不想学字根，用笔顺编码 |

:::warning
切换辅助码方案后，之前记忆的编码会全部失效——不同方案对同一个字的拆分方式不同。建议选定一个方案后坚持使用，不要频繁更换。
:::

各方案在字符覆盖量、规则类型和适用人群上有明显差异，下表提供横向对比，方便选型：

| 方案 | 覆盖字数 | 规则类型 | 学习曲线 | 最适合 |
|------|---------|---------|---------|-------|
| `moqi` | ~6 000 | 部首 + 结构 | 中等 | 汉字结构爱好者，万象默认推荐 |
| `hexing` | ~6 000 | 字形（类五笔） | 中高 | 视觉记忆型，小鹤双拼用户 |
| `zrm` | ~6 000 | 部首 + 笔画 | 中等 | 自然码双拼老用户 |
| `tiger` | ~6 000 | 字根（虎码） | 中高 | 虎码迁移者，追求极低重码率 |
| `wubi` | 五笔全量 | 五笔字根 | 高（已会五笔则为零） | 五笔老用户，辅助码零学习成本 |
| `cangjie` | 仓颉全量 | 仓颉字根 | 高（已会仓颉则为零） | 港台用户，仓颉基础者 |
| `simple_he` | 精简集 | 简化鹤形 | 低 | 辅助码入门首选 |
| `hanxin` | ~5 000 | 笔顺 | 低 | 不想学字根，用笔顺编码 |

### 其他配置项

| 字段 | 类型 | 默认值 | 含义 |
|------|------|--------|------|
| `triggerMode` | `direct` \| `indirect` \| `backtick` | `direct` | 辅助码触发方式，见下方原理机制 |
| `hintEnabled` | boolean | `true` | 是否在候选词旁显示辅助码提示 |
| `hintLength` | number（1-10） | `1` | 对几字以内的候选词显示提示，`1` = 仅单字，`2` = 含两字词 |
| `splitHintEnabled` | boolean | `false` | 是否显示字形拆分路径提示，学习阶段有帮助 |

## 原理机制

### 辅助码的本质

辅助码本质上是附加在拼音编码后的**过滤串**。`script_translator` 在查词典时，如果编码中带有辅助码部分，会对查到的候选词进行额外过滤，只保留辅助码列匹配的字。

词典文件（`.dict.yaml`）中每个字条目除了拼音编码外，还带有辅助码列。例如：

```
你	ni	h
她	ta	v
他	ta	d
它	ta	z
```

当用户输入 `tah`，`script_translator` 先按拼音 `ta` 查到所有「他/她/它/塔/踏……」，再按辅助码 `h` 筛选，只保留辅助码列为 `h` 的字——即「她」。

### 三种 triggerMode 的区别

| 模式 | 输入示例 | 分隔符 | 适合场景 |
|------|---------|--------|---------|
| `direct` | `nih`（你 + 辅助码 h） | 无，直接相连 | 熟练用户，减少按键数 |
| `indirect` | `ni;h`（你 + `;` + 辅助码 h） | `;` | 视觉分隔，可先看候选再追加 |
| `backtick` | `` ni`h ``（你 + `` ` `` + 辅助码 h） | `` ` `` | 最直观，新手推荐 |

`indirect` 和 `backtick` 的优势在于**渐进式输入**：先正常输入拼音看候选词，只有遇到重码时再追加分隔符 + 辅助码，不需要提前规划。

`direct` 模式要求用户在打拼音时就决定是否追加辅助码，更适合已将辅助码内化为肌肉记忆的进阶用户。

### 辅助码提示（hint）的实现

`hintEnabled` 通过 `super_comment` Lua filter 实现。开启后，filter 在每个候选词末尾追加注释，内容就是该字的辅助码编码。`hintLength` 控制显示提示的候选词最大字数：设为 `1` 时只有单字候选显示辅助码，设为 `2` 时两字词也会显示。

`splitHintEnabled` 则进一步展示字形拆分的路径（例如「你」拆分为「亻+尔」），帮助用户理解辅助码的构成逻辑。

## 完整示例

<YamlPreview title="wanxiang.custom.yaml" caption="启用墨奇辅助码，间接触发（; 分隔），双字符提示">

```yaml
patch:
  # 辅助码方案：墨奇码
  auxiliary_code/scheme: moqi
  # 触发方式：间接（; 分隔拼音和辅助码）
  auxiliary_code/trigger: indirect
  # 开启辅助码提示
  auxiliary_code/show_hint: true
  # 提示长度：2（单字和两字词都显示辅助码）
  auxiliary_code/hint_length: 2
  # 开启拆分提示（学习阶段推荐）
  auxiliary_code/split_hint: true
```

</YamlPreview>

:::note
以上 YAML 路径（`auxiliary_code/scheme` 等）对应 rime-ice / 万象拼音方案的实际字段名。如果你使用其他方案，字段名可能不同，请参照方案文档或查看方案 schema 文件中的 `auxiliary_code` 节点。
:::

随着熟练度提升，提示级别也应随之调整。下面给出学习期和熟练期的两段配置供参考：

<YamlPreview title="wanxiang.custom.yaml" caption="学习期与熟练期的 hint 配置对比">

```yaml
# 学习期：对 5 字以内候选词显示完整 2 位辅助码提示
# 信息量最大，适合建立字形记忆
patch:
  super_comment/candidate_length: 5
  super_comment/auxiliary_hint_length: 2

# ——————————————————————————————
# 熟练期：只对单字显示 1 位提示，视觉更干净
# 当你发现大多数提示已是"熟悉的编码"时切换
patch:
  super_comment/candidate_length: 1
  super_comment/auxiliary_hint_length: 1
```

</YamlPreview>

`candidate_length` 控制对几字以内的候选词附加提示注释；`auxiliary_hint_length` 控制提示中显示辅助码的位数（`1` 只显示首码，`2` 显示完整两位）。两者配合使用，可在学习期获得最大信息量，在熟练期保持界面简洁。

## 常见场景

### 消歧同音字：区分「他/她/它」

这是辅助码最典型的用途。三个字拼音完全相同（`ta`），只能靠字形区分：

- 输入 `ta;d` → 「他」（indirect 模式）
- 输入 `ta;v` → 「她」
- 输入 `ta;z` → 「它」

开启提示后，候选词列表中每个字旁边会显示对应辅助码，无需死记。

### 新手学习：hintLength=2 双字符提示

刚开始学辅助码时，把 `hintLength` 设为 `2`，并开启 `splitHintEnabled`。这样不仅单字有提示，常用两字词也会显示，帮助你快速积累高频字的辅助码记忆。一两周后大脑会自然记住最常用的几十个字的辅助码。

### 老手进阶：切换到 direct 模式

当你已经能不假思索地输入高频字的辅助码时，将 `triggerMode` 改为 `direct`。输入「你好」就是 `nihaj`（ni+h 你，hao+j 好），完全不需要额外的分隔按键，输入速度可以进一步提升。

### 跨方案迁移：从 moqi 切换到 hexing

如果你决定从墨奇码切换到鹤形，只需修改 `scheme` 字段，同时**建议先重新开启提示**（`hintEnabled: true`），让自己有一段过渡期重新学习新方案的编码，而不是依赖旧记忆。通常 2-3 周后可以关闭提示转为熟练输入。

<Details title="排错：辅助码不生效" level="advanced">

按以下顺序排查：

1. **方案是否声明了 auxiliary_code 能力**：不是所有 RIME 方案都支持辅助码。检查方案的 `schema.yaml` 文件中是否有 `auxiliary_code` 节点。rime-ice 和万象拼音已内置支持；纯词库方案（如 luna_pinyin）通常不支持。

2. **确认已重新部署**：修改辅助码配置后，必须「重新部署」。单纯保存配置文件不够，RIME 需要重建 prism 才能使新配置生效。

3. **super_comment filter 是否启用**：辅助码提示依赖 `super_comment` Lua filter。确认方案的 filter 列表中包含 `lua_filter@super_comment_filter`。如果提示不显示但辅助码筛选本身可用，这是最可能的原因。

4. **部署后 prism 未重建**：如果辅助码筛选完全不起作用（追加了辅助码但候选词没变化），可能是旧的 prism 文件残留。在 RIME 用户目录的 `build/` 文件夹中删除对应方案的 `.prism.bin` 文件，然后重新部署。

5. **查看部署日志**：RIME 用户目录下的 `rime.log` 记录加载错误。搜索 `[ERROR]` 或 `auxiliary` 关键字定位问题行。

</Details>

<Details title="原理：script_translator 与辅助码的配合" level="advanced">

`script_translator`（脚本翻译器）是 rime-ice / 万象拼音处理拼音编码的核心组件。它与辅助码的配合流程如下：

1. **编码解析**：用户按下按键后，`script_translator` 先尝试从输入序列中识别拼音段和辅助码段。根据 `triggerMode` 的设置，使用不同的解析策略——`direct` 模式靠编码长度推断，`indirect`/`backtick` 模式靠分隔符切割。

2. **词典查询**：用拼音部分在 `.dict.yaml` 中查词。词典中每个字条目在编码列之后有一列辅助码值（由辅助码方案文件决定）。

3. **辅助码过滤**：如果解析出辅助码段，翻译器对查到的候选词集合执行前缀过滤——候选词的辅助码列必须以用户输入的辅助码为前缀才保留。

4. **结果排序**：过滤后的候选词按原有的频率权重重新排序后呈现。辅助码过滤是在排序之前进行的纯过滤操作，不改变权重。

辅助码方案（`aux_code_scheme`）决定词典加载时使用哪张辅助码映射表。映射表文件通常位于方案数据目录（如 `rime-ice/` 下的 `lua/auxiliary_code/` 目录），每种方案一个文件，格式为 `字 → 辅助码` 的键值对。

</Details>

<Details title="自定义辅助码表" level="advanced">

如果内置方案都不满足需求，可以创建自定义辅助码表：

1. **创建辅助码数据文件**，格式为每行一条 `字<TAB>辅助码`：

   ```
   你	hn
   好	vb
   学	ip
   习	nr
   ```

2. **将文件放入方案数据目录**，例如 `<RIME用户目录>/lua/auxiliary_code/custom.txt`。

3. **在 schema.yaml 中引用**（具体字段名参照方案文档，rime-ice 中通常为 `auxiliary_code/dict`）：

   ```yaml
   patch:
     auxiliary_code/dict: custom
   ```

4. **重新部署**。RIME 会加载新的辅助码映射表并重建索引。

自定义辅助码表最常见的用途是：对某个行业词汇（法律、医学、编程）中的专用字补充辅助码，或者完全实现一套自己设计的拆字规则。

</Details>

<Details title="hintLength=1 vs hintLength=2 的学习曲线选择" level="intermediate">

两个值代表不同的学习策略：

**hintLength=1（仅单字）**：候选列表视觉干净，只有真正需要辅助码消歧的单字显示提示。适合已经基本掌握高频字辅助码、希望减少视觉干扰的用户。

**hintLength=2（含两字词）**：更多候选词带有辅助码注释，信息量更大但也更嘈杂。适合学习阶段——你能看到词组中每个字的辅助码，加速记忆积累。代价是候选列表更拥挤，需要更大的候选框或更小的字体。

推荐策略：**入门期用 2，熟练后改为 1**。当你发现候选列表中的辅助码提示已经没有新信息（都是你认识的编码）时，说明可以切换到 `1` 了。

</Details>

<Details title="辅助码记忆策略：从零到熟练的四步法" level="intermediate">

辅助码的学习瓶颈不在于规则复杂，而在于**记忆字数太多**。以下策略帮助你循序渐进地建立肌肉记忆，而不是强行背表：

1. **从 100 个高频字开始**：「的、了、在、是、不……」这些字每天会输入几十次，优先记住它们的辅助码，边打边记，效果远好于专门背诵。开启 `hintEnabled`，看到提示就默念一遍，一周内自然内化。

2. **只在高重码场景启用 hint**：将 `hintLength` 设为 `2`，但把 `candidate_length` 调低到 `3`，让提示只出现在真正有歧义的候选词旁边。减少视觉噪音，让你的注意力集中在真正需要辅助码的字上。

3. **每周复盘错误字**：遇到辅助码记错或忘记的字，用文本文件记下来（字 + 正确辅助码 + 拆分逻辑）。每周回顾一次，重点是理解拆分规则，而不是死记编码。理解规则后，大多数字的辅助码可以推导得出。

4. **配合输入统计看进步**：rime-ice / 万象拼音内置输入统计，定期查看「上屏字数」和「平均选重次数」。辅助码熟练度提升的直接体现是选重次数下降——这个数字比主观感受更客观，也更有激励作用。

</Details>
