# 标点符号映射

标点符号是中文输入体验的重要组成部分。按下英文键盘上的句号 `.`，输出的是中文句号 `。`；按下双引号键，第一次输出左引号 `"`，第二次输出右引号 `"`——这一切都由 RIME 的 punctuator（标点转换器）完成。

## 这是什么

RIME 的 punctuator 是一个「拦截 + 查表替换」的组件，它在用户按下标点键时介入，把 ASCII 标点替换成对应的中文标点输出。

配置分为两个映射表：

- **`punctuator/half_shape`** — 半角模式下的标点映射（日常使用的是这个）
- **`punctuator/full_shape`** — 全角模式下的映射（`full_shape` 开关开启时生效，现代输入场景很少用）

每个键的映射有两种形式：

- **单映射**：按一次直接上屏，如 `'.': "。"`
- **列表映射（rotate）**：每次按键循环输出列表中的下一个，如 `'"': [""", """]` — 第一次按输出 `"`，第二次按输出 `"`，再按又回到 `"`

中英文标点的切换由 `ascii_punct` 开关控制：关闭时输出中文标点，开启时绕过 punctuator 直接输出 ASCII 标点。

:::tip
大多数用户只需要关注 `half_shape` 的配置，`full_shape` 在现代使用场景中极少用到。
:::

## 快速上手

:::note
如果你只需要修改某个标点的映射，完成前四步即可。「原理机制」和进阶内容按需阅读。
:::

<StepGuide>
  <Step title="打开标点符号模块">
    在编辑器左侧导航找到「标点符号映射」模块。页面显示一个表格，左列是键盘输入的 ASCII 字符，右列是对应的中文输出。
  </Step>
  <Step title="修改某个标点映射">
    直接点击右列的输入框进行编辑。**单个输出**直接填写字符，如 `。`；**多个候选**用英文逗号分隔，如 `"，"` 表示 rotate 模式，每次按键循环切换。
  </Step>
  <Step title="添加自定义标点">
    如果表格中没有你想要映射的键，可以在编辑器下方的「自定义」区域手动添加键值对，或者直接在 `custom.yaml` 中用 `patch` 指令追加。
  </Step>
  <Step title="重新部署">
    点击编辑器右上角「保存」，然后触发「重新部署」（macOS：菜单栏输入法图标 → 重新部署；Windows/Linux：对应客户端的部署按钮）。标点映射修改后必须重新部署才能生效。
  </Step>
  <Step title="测试输入">
    在任意输入框测试：按下已修改的标点键，确认输出符合预期。若未生效，检查是否完成了重新部署，或参考下方「排错」进阶区。
  </Step>
</StepGuide>

## 配置项详解

### 常用默认映射

以下是 `half_shape` 的常用默认映射，覆盖日常中文写作的绝大多数标点需求：

| 键（输入） | 默认输出 | 说明 |
|-----------|---------|------|
| `.` | `。` | 中文句号 |
| `,` | `，` | 中文逗号 |
| `?` | `？` | 中文问号 |
| `!` | `！` | 中文感叹号 |
| `;` | `；` | 中文分号 |
| `:` | `：` | 中文冒号 |
| `` ` `` | `、` | 顿号（部分配置用反引号） |
| `(` | `（` | 中文左括号 |
| `)` | `）` | 中文右括号 |
| `[` | `【` | 中文左方括号 |
| `]` | `】` | 中文右方括号 |
| `{` | `「` | 直角左引号 |
| `}` | `」` | 直角右引号 |
| `<` | `《` | 书名号左 |
| `>` | `》` | 书名号右 |
| `"` | `[", "]` | 弯双引号（rotate：左 → 右 → 左…） |
| `'` | `[', ']` | 弯单引号（rotate：左 → 右 → 左…） |

### 单映射 vs 列表映射（rotate）的区别

**单映射**：键对应一个字符串，按键直接上屏。

```yaml
punctuator:
  half_shape:
    '.': "。"     # 按 . 始终输出 。
    '?': "？"     # 按 ? 始终输出 ？
```

**列表映射（rotate）**：键对应一个列表，每次按键输出列表中的下一项，循环往复。常用于引号的自动配对：

```yaml
punctuator:
  half_shape:
    '"': [""", """]     # 第1次按 → "，第2次按 → "，第3次又回到 "
    "'": ["'", "'"]     # 第1次按 → '，第2次按 → '
```

:::note
Rotate 机制的计数是**全局**的，不区分当前光标位置或上下文。如果你中途切走又切回，计数不会重置。这是 RIME 的已知行为，了解它可以避免引号配对时出现意外。
:::

## 原理机制

### punctuator 在 RIME 引擎中的角色

punctuator 实际上由两个子组件组成，在 schema 的 `engine` 中分别注册：

- **`punctuation_processor`（Processor）**：在键盘事件层面拦截标点键，判断当前是否处于中文标点模式。
- **`punct_translator`（Translator）**：把被拦截的标点键翻译成候选词——单映射直接生成一个候选上屏，列表映射展示多个候选（或 rotate）。

用户按下 `.` 键后，引擎的处理顺序大致如下：

```
键盘事件 → ascii_composer（判断是否英文模式）
         → key_binder（判断是否触发按键绑定）
         → punctuation_processor（拦截标点键）
              ↓ 查 half_shape / full_shape 表
         → punct_translator（生成候选）
              ↓ 单映射：直接上屏
              ↓ 列表映射：rotate 或展示候选列表
```

### half_shape vs full_shape 的切换

哪张表生效，取决于 `full_shape` 开关的状态：

| `full_shape` 开关 | 生效的映射表 |
|-----------------|------------|
| 关闭（默认）| `punctuator/half_shape` |
| 开启 | `punctuator/full_shape` |

### ascii_punct 开关的作用

当 `ascii_punct` 开关开启时，punctuation_processor **不拦截**标点键，按键直接透传给操作系统，输出 ASCII 标点。这与在 `half_shape` 里把每个键都映射回 ASCII 不同——`ascii_punct` 是绕过整个 punctuator，而不是修改映射表。

## 完整示例

<YamlPreview title="luna_pinyin.custom.yaml" caption="自定义标点映射：添加 & 键映射，并把 ; 改为直接输出英文分号">

```yaml
patch:
  punctuator/half_shape/&:
    - "＆"
    - "&"
  punctuator/half_shape/;: ";"
```

</YamlPreview>

:::note
`patch` 路径中的 `/` 是 patch 的键路径分隔符，不是 YAML 嵌套。`punctuator/half_shape/&` 表示「在 `punctuator.half_shape` 节点下设置 `&` 键的值」，不会影响其他键的映射。
:::

## 常见场景

### 英文引号 vs 中文引号

默认配置输出弯引号 `""`。如果你更喜欢直角引号 `「」`（常见于港台排版规范），可以覆盖 `"` 和 `'` 的映射：

```yaml
patch:
  punctuator/half_shape/'"':
    - "「"
    - "」"
  punctuator/half_shape/"'":
    - "『"
    - "』"
```

如果想恢复英文原始引号（适合写作时插入英文引用），开启 `ascii_punct` 开关即可临时切换。

### 代码用户：保留 ASCII 分号和括号

写中文注释时，有时需要在中文模式下输出英文标点（如分号 `;`、括号 `()`）。可以针对常用的符号单独映射回 ASCII：

```yaml
patch:
  punctuator/half_shape/;: ";"
  punctuator/half_shape/(:
    - "("
    - "（"
  punctuator/half_shape/):
    - ")"
    - "）"
```

这样分号直接输出 `;`，括号则 rotate 在英文和中文之间切换。

### Markdown 友好：保留反引号和星号

在 Markdown 写作场景中，反引号 `` ` `` 和星号 `*` 通常需要保留 ASCII 原意：

```yaml
patch:
  punctuator/half_shape/"`": "`"
  punctuator/half_shape/*: "*"
```

注意：部分默认配置里反引号映射到顿号 `、`，如果你用 Markdown 写作，这里需要显式覆盖。

### 自定义顿号输入

顿号 `、` 在不同方案里的默认键位不统一，有的是反引号，有的是反斜杠。统一到一个你习惯的键：

```yaml
patch:
  punctuator/half_shape/\\: "、"   # 反斜杠 → 顿号
  punctuator/half_shape/"`": "、"  # 反引号 → 顿号（二选一）
```

### 全角括号与方括号

默认的 `[` 映射到 `【】`（书名号风格的方括号），`{` 映射到 `「」`（直角引号）。如果你更需要全角圆括号和花括号：

```yaml
patch:
  punctuator/half_shape/(:
    - "（"
    - "）"
  punctuator/half_shape/{:
    - "｛"
    - "｝"
```

<Details title="排错：标点映射不生效" level="advanced">

按以下顺序排查：

1. **确认已重新部署**：修改标点映射后必须「重新部署」，仅保存文件不够。macOS 点击菜单栏输入法图标 → 重新部署；Windows/Linux 使用对应客户端的部署按钮。

2. **检查 ascii_punct 开关状态**：如果 `ascii_punct` 当前处于开启状态，所有标点键都会绕过 punctuator 直接输出 ASCII，映射不会生效。检查方法：按 `Ctrl+.`（或你绑定的切换键）切换状态，看候选框上方是否有「英文标点」提示。

3. **检查 patch 写法**：`punctuator/half_shape/键名` 中键名如果是特殊字符（如 `"`、`'`、`\`），需要用引号包裹：

   ```yaml
   # 错误：裸写引号会让 YAML 解析失败
   patch:
     punctuator/half_shape/": [""", """]

   # 正确：用单引号包裹键名
   patch:
     punctuator/half_shape/'"': [""", """]
   ```

4. **检查是否与 key_binder 冲突**：如果某个标点键被 `key_binder` 绑定了快捷键（如 `;` 绑定到特定功能），key_binder 会在 punctuator 之前处理该键，导致标点映射失效。检查 `key_binder/bindings` 中是否有该键的绑定。

5. **查看部署日志**：RIME 用户目录下的 `rime.log` 记录加载错误。搜索 `[ERROR]` 或 `punctuator` 关键字定位问题行。

</Details>

<Details title="原理：punctuator 在引擎处理链中的位置" level="advanced">

RIME 的按键处理是一个 **Processor 链**，按顺序依次传递键盘事件，第一个消费该事件的 Processor 获胜，后续 Processor 不再处理。

典型的 Processor 顺序（从 schema.yaml 的 `engine/processors` 读取）：

```
ascii_composer       # 处理 CapsLock / Shift 切换
recognizer           # 识别特定输入前缀（如 / 开头的反查）
key_binder           # 处理快捷键绑定
speller              # 处理拼写输入（字母键）
punctuation_processor # 处理标点键
selector             # 处理候选选择键（数字、上下箭头）
navigator            # 处理光标移动键
express_editor       # 处理 Enter、Backspace
```

`punctuation_processor` 在 `key_binder` 之后、`selector` 之前。这意味着：

- 如果 `key_binder` 已经消费了某个标点键（如把 `;` 绑定到二分上屏），`punctuation_processor` 就看不到这个键了。
- 在候选窗口打开时，标点键通常先经过 `selector`，某些标点键可能触发选词而非输出标点。

了解这个顺序，可以帮助你判断标点行为异常时是哪个组件在干预。

</Details>

<Details title="自定义复杂标点：多字符序列与颜文字映射" level="advanced">

RIME 的 punctuator 映射表的值支持多字符字符串，不限于单个 Unicode 码位。利用这一点，可以实现一些有趣的映射。

**映射到多字符字符串**（如省略号、破折号）：

```yaml
patch:
  punctuator/half_shape/-:
    - "——"    # 破折号（两个 em dash）
    - "–"     # en dash
    - "-"     # 保留连字符
  punctuator/half_shape/~:
    - "……"    # 省略号（两个 …）
    - "～"    # 全角波浪号
```

**注意**：RIME punctuator 设计上以「一次按键输出一个候选」为主，候选的内容可以是多字符字符串，但**不支持把多个按键序列（如 `:)`）映射为一个输出**——那需要借助 `recognizer` + 自定义 `translator` 或 Lua 脚本来实现，属于更复杂的定制方案。

如果你的目标是输入特定前缀（如 `/ywy`）触发表情输出，应该使用「特殊输入」模块中的自定义触发器，而非 punctuator 映射。

</Details>

<Details title="单映射 vs 列表映射的选择建议" level="intermediate">

什么时候用单映射，什么时候用列表映射（rotate），取决于你对这个键的使用习惯：

| 场景 | 推荐方式 | 示例 |
|------|---------|------|
| 该键始终只输出一种字符 | 单映射（字符串） | `'.': "。"` |
| 该键有多种候选，希望循环切换 | 列表映射（rotate） | `'"': [""", """]` |
| 该键同时需要中英文两种选项 | 列表映射 | `';': [";", "；"]` |
| 需要左右配对的括号/引号 | 列表映射 | `'(': ["（", "）"]` |

**列表映射的使用体验**：rotate 是「无感知」切换，不弹出候选窗，按键即输出。对于引号这类天然成对的符号，rotate 是最流畅的方式。但如果列表中有超过 2 个候选，rotate 顺序要仔细设计，否则容易按错。

**性能方面**：单映射和列表映射在性能上没有明显差异，可以完全按照使用习惯选择。

</Details>
