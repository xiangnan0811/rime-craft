# 模糊音规则

模糊音是为方言用户和发音习惯不同的用户准备的「容错机制」——如果你分不清前后鼻音或平翘舌音，开启对应的模糊音规则后，RIME 会把它们视为等价，让你不需要纠结发音就能打出正确的字。

## 这是什么

普通话中有一些发音非常接近的声母和韵母对，很多地区的方言并不区分它们。例如湖南、四川用户往往不区分 `z/zh`、`c/ch`、`s/sh`（平翘舌），湖南、湖北用户常常混淆 `l` 和 `n`，而全国大多数地区的人都程度不同地混淆前鼻音（`an/en/in`）和后鼻音（`ang/eng/ing`）。

RIME 通过 `speller/algebra`（拼写运算列表）实现模糊音。每一条规则是一个正则变换指令，告诉 RIME 拼写引擎：当遇到某种拼音时，同时也接受另一种拼音。这样，输入 `niao` 时也能搜索 `liao` 的候选，输入 `fen` 时也能搜索 `feng`。

:::warning
模糊音的代价是**重码增加**。每开启一组规则，原本不同音的字就被视为同音字，候选词列表会变长。建议只开启你**确实需要**的组合，而不是全部开启。
:::

## 快速上手

:::tip
如果你只想消除某类拼写错误（比如平翘舌不分），完成前四步即可。「原理机制」和进阶内容按需阅读。
:::

<StepGuide>
  <Step title="打开模糊音模块">
    在编辑器左侧导航找到「模糊音规则」模块。页面分为两部分：上方是声母模糊，下方是韵母模糊。每条规则都有独立的开关。
  </Step>
  <Step title="选择需要的规则">
    根据自己的发音习惯开启对应规则。常见选择：
    - **平翘舌不分**：开启 `z ↔ zh`、`c ↔ ch`、`s ↔ sh`
    - **边鼻音不分**：开启 `l ↔ n`
    - **前后鼻音不分**：开启 `an ↔ ang`、`en ↔ eng`、`in ↔ ing`

    建议先只开启最影响你的 1–2 组，观察一段时间再决定是否继续扩展。
  </Step>
  <Step title="保存并重新部署">
    点击编辑器右上角「保存」，然后触发「重新部署」（macOS：菜单栏输入法图标 → 重新部署；Windows/Linux：对应客户端的部署按钮）。**修改 algebra 规则后必须重新部署才能生效。**
  </Step>
  <Step title="测试输入">
    在任意输入框测试：
    - 开启了 `l ↔ n` 后，输入 `niao` 应出现「鸟/了」等候选
    - 开启了 `an ↔ ang` 后，输入 `zan` 应出现「赞/脏」等候选
    若未生效，检查是否完成了重新部署，或查看下方「排错」进阶区。
  </Step>
</StepGuide>

## 配置项详解

所有预设规则来自 `fuzzy-rules.ts`，分为声母和韵母两类。

### 声母模糊音

| 规则 ID | 标签 | 代表字对 | 正则变换 | 典型地区 |
|---------|------|---------|---------|---------|
| `z_zh` | `z ↔ zh` | 子/知不分 | `derive/^([zcs])h/$1/` + `derive/^([zcs])([^h])/$1h$2/` | 湖南、四川、广东等 |
| `c_ch` | `c ↔ ch` | 此/吃不分 | 同上（三组共用一组规则） | 同上 |
| `s_sh` | `s ↔ sh` | 思/诗不分 | 同上 | 同上 |
| `l_n` | `l ↔ n` | 南/兰不分 | `derive/^l/n/` + `derive/^n/l/` | 湖南、湖北、江西等 |
| `f_h` | `f ↔ h` | 飞/灰不分 | `derive/^f/h/` + `derive/^h/f/` | 广东、广西等 |
| `r_l` | `r ↔ l` | 人/林不分 | `derive/^r/l/` + `derive/^l/r/` | 部分南方地区 |

### 韵母模糊音

| 规则 ID | 标签 | 代表字对 | 正则变换 | 影响范围 |
|---------|------|---------|---------|---------|
| `an_ang` | `an ↔ ang` | 安/昂不分 | `derive/([ei])n$/$1ng/` + `derive/([ei])ng$/$1n/` | 全国最广，影响最大 |
| `en_eng` | `en ↔ eng` | 恩/鞥不分 | 同上（三组共用一组规则） | 同上 |
| `in_ing` | `in ↔ ing` | 因/英不分 | 同上 | 同上 |
| `ian_iang` | `ian ↔ iang` | 烟/央不分 | `derive/ian$/iang/` + `derive/iang$/ian/` | 部分地区 |
| `uan_uang` | `uan ↔ uang` | 弯/王不分 | `derive/uan$/uang/` + `derive/uang$/uan/` | 部分地区 |

## 原理机制

### speller/algebra 是什么

RIME 的拼写引擎（`speller`）负责把用户的击键序列转换成可查词典的编码。`algebra` 是一个**有序规则列表**，每条规则描述一种编码变换。常见的变换类型有四种：

| 指令 | 作用 | 模糊音用途 |
|------|------|---------|
| `derive` | 在原有编码上**额外**生成新编码，原编码保留 | 最常用——派生出模糊拼音，不破坏原始输入 |
| `abbrev` | 允许缩略输入，原编码保留 | 首字母缩写（如 `abbrev/^([a-z]).+$/$1/`） |
| `xform` | **替换**原有编码（原编码消失） | 不适用于模糊音，通常用于双拼映射 |
| `erase` | 删除某些合法编码 | 禁用某个特殊拼音时使用 |

模糊音使用 `derive`，因为它只添加新的合法编码，不删除已有的——正确拼音和模糊拼音都可以匹配，对已经记住正确发音的用户毫无影响。

### 规则按顺序执行

`algebra` 列表的规则**从上到下依次执行**，每条规则的输入是前一条规则的输出结果。这一点会在链式推导中产生重要影响。

例如，如果同时启用 `z_zh`（平翘舌）和 `l_n`（边鼻音），规则执行顺序如下：

```
原始拼音: "zhi"
→ 经过 derive/^([zcs])h/$1/ → 额外生成 "zi"
→ 经过 derive/^l/n/ → 对 "zhi"/"zi" 都不影响（无 l 开头）
最终：同时接受 "zhi" 和 "zi"
```

:::note
`derive` 不修改原条目，而是**克隆并变换**后追加。规则越多，最终合法编码集合越大，词典查询量也越大，但通常对速度影响可忽略不计。
:::

### prism 编译

所有 `algebra` 规则在方案**重新部署**时被编译成 **prism**（前缀索引树）。prism 是 RIME 的核心数据结构，它把词典中的所有词条按照 algebra 变换后的编码重新建立索引。这就是为什么：

1. 修改 algebra 后必须重新部署——部署过程包含 prism 的重建
2. 模糊音的匹配速度和词条数量成正比，而不是和 algebra 规则数量成正比

## 完整示例

<YamlPreview title="luna_pinyin.custom.yaml" caption="启用 z/c/s ↔ zh/ch/sh 不分 + l/n 不分，适合南方普通话用户">

```yaml
patch:
  speller/algebra/+:
    - derive/^([zcs])h/$1/
    - derive/^([zcs])([^h])/$1h$2/
    - derive/^l/n/
    - derive/^n/l/
```

</YamlPreview>

:::note
`speller/algebra/+` 中的 `+` 表示**追加**到现有 algebra 列表末尾，而不是替换整个列表。这样可以保留方案原有的其他 algebra 规则（如 `abbrev` 首字母缩写）。如果使用 `speller/algebra:`（无加号），则会替换整个列表，需要把所有规则都写全。
:::

## 常见场景

### 南方普通话：平翘舌 + 边鼻音不分

湖南、四川、广东等地区最典型的需求：

```yaml
patch:
  speller/algebra/+:
    - derive/^([zcs])h/$1/
    - derive/^([zcs])([^h])/$1h$2/
    - derive/^l/n/
    - derive/^n/l/
```

### 前后鼻音不分（最保守策略）

大多数人最常犯的错误是前后鼻音。只开这三组，影响最小，重码增加也最少：

```yaml
patch:
  speller/algebra/+:
    - derive/([ei])n$/$1ng/
    - derive/([ei])ng$/$1n/
    - derive/ian$/iang/
    - derive/iang$/ian/
```

这组规则同时覆盖了 `an/ang`、`en/eng`、`in/ing`（通过 `[ei]n` 捕获组），以及 `ian/iang`。

### 方言影响：f/h 互通

部分粤语、闽南语背景用户分不清 `f` 和 `h`（「飞」读成「灰」的音）：

```yaml
patch:
  speller/algebra/+:
    - derive/^f/h/
    - derive/^h/f/
```

注意这组规则会让 `h` 开头的字也出现在 `f` 的候选中，重码增加相对明显，建议按实际需要使用。

### 快速输入：首字母缩略

这不是模糊音，但也是 `algebra` 的常见用途——允许只输入首字母选词：

```yaml
patch:
  speller/algebra/+:
    - abbrev/^([a-z]).+$/$1/
```

开启后输入 `z` 可能匹配「在/做/这/中……」等大量字，适合配合辅助码使用。

### 综合方案：南方用户全配置

```yaml
patch:
  speller/algebra/+:
    - derive/^([zcs])h/$1/
    - derive/^([zcs])([^h])/$1h$2/
    - derive/^l/n/
    - derive/^n/l/
    - derive/([ei])n$/$1ng/
    - derive/([ei])ng$/$1n/
```

<Details title="排错：模糊音规则不生效" level="advanced">

按以下顺序排查：

1. **确认已重新部署**：修改任何 algebra 规则后，必须「重新部署」才能重建 prism。macOS 点击菜单栏输入法图标 → 重新部署；Windows/Linux 使用对应客户端的部署按钮。单纯保存配置文件**不够**，必须触发部署。

2. **检查 patch 语法**：`speller/algebra/+` 中的 `/` 是 patch 的路径分隔符，不是 YAML 嵌套。常见错误写法：

   ```yaml
   # 错误：这会替换整个 speller 节点，清空原有所有 algebra 规则
   patch:
     speller:
       algebra:
         - derive/^l/n/
   ```

   正确写法：

   ```yaml
   patch:
     speller/algebra/+:
       - derive/^l/n/
   ```

3. **algebra 顺序影响**：若规则之间有依赖关系（前一条规则的输出是后一条规则的输入），顺序错误会导致规则不生效。建议把 `abbrev`（缩略）类规则放在 `derive` 之后，因为 `abbrev` 需要在完整拼音上操作。

4. **特定词未被 prism 收录**：模糊音让更多编码变合法，但如果词典本身没有收录某个字/词，模糊音也无法让它出现。可以通过「词典管理」补充词条。

5. **查看部署日志**：RIME 用户目录下的 `rime.log` 记录加载错误。搜索 `[ERROR]` 或 `speller` 关键字定位问题行。

</Details>

<Details title="原理：algebra 规则的编译顺序与链式推导" level="advanced">

`algebra` 列表中的规则按顺序**逐条**作用于编码集合。每条规则处理完毕后，**结果集合**（包含原始编码和所有 derive 出的新编码）作为下一条规则的输入。

**示例：链式推导**

假设同时有两条规则：

```yaml
- derive/^n/l/      # n 开头 → l 开头
- derive/^l/r/      # l 开头 → r 开头
```

对于拼音 `nan`，执行过程：

```
初始集合: {nan}
经第1条: {nan, lan}        # derive n→l，新增 lan
经第2条: {nan, lan, ran}   # derive l→r，对 lan 也生效，新增 ran
最终合法编码: nan / lan / ran 全部可匹配
```

这意味着**规则的相对顺序会决定能否产生链式推导**。若两条规则顺序对调：

```yaml
- derive/^l/r/      # 先执行：初始集合只有 nan，l→r 无效
- derive/^n/l/      # 后执行：{nan, lan}，l→r 已不再执行
最终合法编码: nan / lan（没有 ran）
```

实践中，若不需要链式推导（大多数模糊音场景），顺序无关紧要；若有依赖关系，需要明确安排顺序。

</Details>

<Details title="自定义模糊音规则" level="advanced">

预设规则不够用时，可以手写自定义 `derive` 规则。RIME 的正则引擎使用 **Oniguruma**（Ruby 同款），语法与 PCRE 大体相同。

**基本语法**：

```
derive/<匹配模式>/<替换结果>/
```

- `^` 匹配编码开头（声母位置）
- `$` 匹配编码结尾（韵尾位置）
- `([...])` 捕获组，用 `$1`、`$2` 回引
- `[^h]` 匹配「不是 h 的字符」

**示例：自定义 ü → v 兼容（lv/nv 输入 lü/nü）**

```yaml
patch:
  speller/algebra/+:
    - derive/^([ln])ü/$1v/    # 允许用 v 代替 ü
```

**示例：兼容 v 代 ü（反向）**

```yaml
patch:
  speller/algebra/+:
    - derive/^([ln])v/$1ü/    # 将 v 映射回 ü
```

**测试方法**：修改 custom.yaml 后重新部署，在输入框中测试目标拼音。若不生效，检查正则语法，或查看 `rime.log` 中的编译报错。Oniguruma 不支持 `\w`、`\d` 等 PCRE 扩展语法，请使用 `[a-z]`、`[0-9]` 等字符类。

</Details>

<Details title="derive vs xform vs abbrev 何时用哪个" level="intermediate">

选择哪种 algebra 指令，取决于你是否需要保留原始编码：

| 场景 | 推荐指令 | 原因 |
|------|---------|------|
| 模糊音（两种拼音都能输入） | `derive` | 保留原编码，额外增加新编码 |
| 双拼映射（键位→拼音） | `xform` | 替换编码，原始键序列没有保留意义 |
| 首字母缩写 | `abbrev` | 专门用于缩略，语义清晰 |
| 禁用某个拼音 | `erase` | 从合法编码集合中移除 |

**`derive` vs `xform` 的核心区别**：

- `derive`：`{nan}` → `{nan, lan}`（原始保留）
- `xform`：`{nan}` → `{lan}`（原始丢失）

模糊音必须用 `derive`，因为正确拼音的用户不应受到影响。若误用 `xform`，会导致正确拼音反而无法输入。

**`abbrev` 的特殊性**：

`abbrev` 与 `derive` 在行为上相似，但语义不同——`abbrev` 产生的编码在 RIME 内部被标记为「缩略」，在整句模式下会降低优先级，避免单字母把整句候选挤掉。

</Details>
