# 候选词设置

候选词面板是输入法最核心的交互界面。候选词设置控制候选的生成策略、排序逻辑与显示数量，直接决定你每次输入的选词效率。

## 这是什么

当你输入拼音时，RIME 会把编码交给 **Translator（翻译器）** 组件，翻译器查询词典并输出候选词列表，再由 Filter 过滤排序后呈现在面板上。

「候选词设置」控制三个层面：

- **基础显示**：每页候选词数量（`page_size`）和选词键（`select_keys`）
- **翻译行为**：是否开启输入补全、整句模式、用户词典
- **词组策略**：词长上限、同音/同形字上限、排序初始权重

`page_size` 与 `select_keys` 存储在 `DefaultConfig`（全局生效）；翻译器参数存储在各方案的 `TranslatorConfig` 下。

## 快速上手

:::tip
如果你只想调整候选词数量和选词键，完成前三步即可。翻译器参数保持默认对大多数用户已经足够好。
:::

<StepGuide>
  <Step title="打开候选词设置">
    在编辑器左侧导航找到「候选词设置」模块。页面分为两部分：上方是基础显示设置，下方「高级设置」折叠区包含翻译器参数。
  </Step>
  <Step title="设置每页候选词数量">
    「每页候选词数量」下拉选择 5–9 之间的值。建议：
    - **全拼用户**：5 个，精准选词翻页少
    - **双拼用户**：7–9 个，字母键选词配合更多候选
    - **配合辅助码**：5 个即够，辅助码会把候选缩减到 1–3 个
  </Step>
  <Step title="设置选词键">
    「选词按键」默认为数字键 1–5（或更多）。双拼用户推荐切换为「字母键 ASDFGHJKL」，手指始终停留在主键盘区。
  </Step>
  <Step title="按需调整翻译器开关">
    展开「高级设置」，根据你的输入习惯调整：
    - **整句模式**：习惯连续输入整句的用户保持开启；逐词选字、配合辅助码的用户建议关闭
    - **输入补全**：保持开启（输入未完成音节时显示候选）
    - **用户词典**：保持开启（记录常用词，自动调频）
  </Step>
</StepGuide>

## 配置项详解

### 基础显示（DefaultConfig）

| 编辑器字段 | YAML 键 | 默认值 | 说明 |
|-----------|---------|--------|------|
| 每页候选词数量 | `menu/page_size` | `5` | 每页显示多少个候选词 |
| 选词按键 | `menu/alternative_select_keys` | `"12345"` | 数字或字母键选词 |

### 翻译器参数（TranslatorConfig → `translator/` 前缀）

| 编辑器字段 | YAML 键 | 默认值 | 说明 |
|-----------|---------|--------|------|
| 输入补全 | `translator/enable_completion` | `true` | 未完成音节也显示候选 |
| 整句模式 | `translator/enable_sentence` | `true` | 多音节自动组合成句 |
| 用户词典 | `translator/enable_user_dict` | `true` | 学习使用习惯、自动调频 |
| 翻译器优先级 | `translator/initial_quality` | `1.2` | 候选词初始排序权重 |
| 核心词最大长度 | `translator/core_word_length` | `4` | 造句时使用的最长词组 |
| 候选词最大长度 | `translator/max_word_length` | `7` | 候选列表中词组字数上限 |
| 同音词上限 | `translator/max_homophones` | `8` | 同一拼音下的候选词数量上限 |
| 同形词上限 | `translator/max_homographs` | `8` | 同字形多音字的变体数量上限 |
| 拼音提示 | `translator/spelling_hints` | `30` | 注释栏显示拼音提示的候选词长度阈值 |
| 始终显示注释 | `translator/always_show_comments` | `true` | 强制在候选词旁显示注释（辅助码等） |

## 原理机制

### Translator 在 RIME 引擎中的位置

RIME 处理一次输入的流程：

```
按键输入 → Processor → Segmentor → Translator → Filter → 候选列表呈现
```

`script_translator`（拼音）和 `table_translator`（码表）是 RIME 内置的两类主要翻译器。`TranslatorConfig` 的参数直接作用于方案使用的 `translator` 组件。

### 用户词典（user_dict）

用户词典文件（`<schema_id>.userdb/`）独立于主词典存储，记录：

1. **调频数据**：每次上屏都更新候选权重，常用词自动靠前
2. **自造词**：连续选字后自动生成的自定义词组

关闭 `enable_user_dict` 后词典文件仍保留，重新开启即恢复历史调频数据。

### `initial_quality` 与多翻译器排序

当方案同时挂载多个翻译器（例如 `script_translator` + 英文 `table_translator`），每个翻译器产生的候选带有各自的质量分（`quality`）。最终候选合并时按质量分降序排列：

```
最终质量分 = initial_quality × 词典权重 × 用户调频系数
```

调高某个翻译器的 `initial_quality` 可让其候选整体靠前。单翻译器方案中此值对排序无实质影响。

### `core_word_length` 与 prism 索引

`core_word_length` 控制造句引擎在 **prism**（前缀索引树）中检索词条时的最长前缀长度。值越大，能匹配的长词组越多，但每次击键触发的词典查询量也线性增加。默认值 4 对应绝大多数 2–4 字常用词，是速度与质量的平衡点。

## 完整示例

<YamlPreview title="my_schema.custom.yaml" caption="通过 patch 覆盖翻译器参数——仅列出需要修改的字段即可">

```yaml
patch:
  menu/page_size: 7
  menu/alternative_select_keys: "ASDFGHJKL"
  translator/enable_completion: true
  translator/enable_sentence: false     # 关闭整句，习惯逐词选字
  translator/enable_user_dict: true
  translator/initial_quality: 1.2
  translator/core_word_length: 4
  translator/max_word_length: 7
  translator/max_homophones: 8
  translator/max_homographs: 8
  translator/spelling_hints: 30
  translator/always_show_comments: true
```

</YamlPreview>

:::note
`patch` 是追加/覆盖语义，只需填写需要更改的字段。未列出的字段保持方案默认值，不会被清空。
:::

## 常见场景

- **全拼用户（整句输入）**：`page_size: 5`，整句模式开启，用户词典开启，依赖调频让常用词靠前。
- **双拼用户**：`page_size: 7` + `alternative_select_keys: "ASDFGHJKL"`，手指不离主键盘区，7 个候选减少翻页。
- **配合辅助码精准选字**：关闭 `enable_sentence`，减小 `max_homophones` 到 5，辅助码已精确过滤，候选列表无需太多。
- **禁止输入法学习记录**：关闭 `enable_user_dict`，候选排序完全由词典决定，不记录任何上屏行为。
- **多翻译器混合方案（拼音 + 英文）**：调高主翻译器 `initial_quality`（如 `1.5`），确保中文候选整体优先于英文候选。

---

<Details title="core_word_length 与 max_word_length 深入辨析" level="intermediate">

这两个参数常被混淆，但作用层次不同：

| 参数 | 作用阶段 | 影响对象 |
|------|---------|---------|
| `core_word_length` | **造句阶段**（Translator 内部） | 造句引擎检索词条时的最长词组，影响造句质量和速度 |
| `max_word_length` | **输出阶段**（候选列表） | 最终呈现给用户的候选词最大字数，超过此值的候选被丢弃 |

**典型案例**：

- `core_word_length: 6, max_word_length: 4`：造句时会检索 6 字词组（保证句子连贯），但候选列表只展示 4 字以内的词——适合偏好短候选但又希望整句质量好的用户。
- `core_word_length: 3, max_word_length: 10`：造句用短词（速度快），但允许长候选出现——适合手动选词为主、偶尔需要长词组的用户。

通常两者保持接近或相同（`core_word_length ≤ max_word_length`）效果最自然。

</Details>

<Details title="排错：翻译器配置不生效" level="advanced">

按以下顺序排查：

1. **确认已重新部署**：RIME 配置修改后必须「重新部署」才生效。macOS 点击菜单栏图标 → 重新部署；Windows/Linux 使用对应客户端的部署按钮。

2. **检查 patch 语法**：`translator/enable_sentence: false` 中的 `/` 是 patch 的路径分隔符，不是 YAML 嵌套。如果误写成：
   ```yaml
   # 错误写法——这会替换整个 translator 节点
   patch:
     translator:
       enable_sentence: false
   ```
   会导致其他翻译器字段被清空。正确做法是用 `/` 路径写法逐字段覆盖。

3. **确认作用于正确的方案**：`TranslatorConfig` 参数作用于 `schemaConfigs[primarySchemaId]`，即方案列表第一个方案。如果你修改的是次级方案，需要对应方案的 `custom.yaml`。

4. **用户词典锁定**：如果 RIME 异常退出，`.userdb/` 目录下可能残留 `.lock` 文件，导致用户词典无法写入。手动删除锁文件后重新部署。

5. **查看部署日志**：RIME 用户目录下的 `rime.log` 会记录加载错误。搜索 `[ERROR]` 或 `translator` 定位问题行。

</Details>

<Details title="原理：多 translator 链协同" level="advanced">

RIME schema 的翻译器链通过 `engine/translators` 数组配置。万象拼音典型配置类似：

```yaml
engine:
  translators:
    - punct_translator          # 标点直出
    - script_translator         # 拼音翻译器（TranslatorConfig 作用于此）
    - table_translator@english  # 英文词典
    - lua_translator@date_time  # Lua 特殊输入
```

每个翻译器**独立**产出候选列表，`initial_quality` 是该翻译器产出候选的基础分。RIME 的 `merge_translators` 逻辑将所有候选按 `quality` 归并排序后交给 Filter 链。

用 `+` 追加翻译器（不替换原有列表）：

```yaml
patch:
  engine/translators/+:
    - lua_translator@my_tool    # 追加，不覆盖原有翻译器
```

如果需要调整某个翻译器在链中的位置，使用 `@before` / `@after` 修饰符（需 RIME 0.15+）：

```yaml
patch:
  engine/translators/+:
    - lua_translator@my_tool@before script_translator
```

</Details>

<Details title="维护：用户词典升级与迁移" level="advanced">

**用户词典文件位置**

RIME 用户目录下的 `<schema_id>.userdb/` 文件夹（LevelDB 格式）存储调频和自造词数据。

**跨设备同步**

将用户目录整体纳入 iCloud / Syncthing / Git 同步。注意：

- `.userdb/` 目录下有 LevelDB 的 `LOCK` 文件，同步工具可能产生冲突。推荐在 RIME 未运行时同步，或使用支持「不同步锁文件」规则的同步方案。
- 不同平台（macOS / Windows / Linux）的用户目录路径不同，参考 [多设备同步](./multi-device-sync)。

**用户词典损坏修复**

若词典损坏（表现为部署报错或调频数据丢失）：

1. 关闭所有 RIME 进程
2. 备份 `<schema_id>.userdb/` 文件夹
3. 删除该文件夹，重新部署——RIME 会自动创建空白词典
4. 如果有 `.txt` 格式的词典导出备份（通过 `rime_dict_manager` 导出），可重新导入

**升级方案版本**

升级万象拼音等方案时，主词典（`.dict.yaml`）可能新增词条，但不会影响用户词典中已有的调频数据。若新版本调整了词库结构，建议通过 `rime_dict_manager` 导出旧词典，升级后重新导入。

:::warning
直接删除 `.userdb/` 目录会永久清空调频和自造词数据，操作前请务必备份。
:::

</Details>
