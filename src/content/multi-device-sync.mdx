# 多设备同步

RIME 的配置和用户词典默认保存在本地用户目录，各设备互相独立。当你在家用 Mac、公司 Windows 和手机上都装了 RIME，任何一台设备上花时间调校的方案、积累的用户词频都无法自动出现在其他设备上。本文介绍三种同步方案，以及每种方案的适用场景和注意事项。

## 这是什么

「同步」在 RIME 语境下有两层含义：

1. **配置同步**：把 `*.custom.yaml`、Lua 脚本、自定义短语等 _源文件_ 同步到各设备，让所有设备使用相同的方案配置。
2. **用户词典同步**：把 `*.userdb/` 目录（记录输入历史和个人词频的 B+ 树数据库）同步到各设备，让词频学习在多台设备间共享。

两件事可以分开处理，也可以一起解决——取决于你选择的同步方式。

## 同步哪些文件

| 文件 / 目录 | 是否同步 | 说明 |
|-------------|----------|------|
| `*.custom.yaml` | ✅ 同步 | 用户覆盖配置，核心文件 |
| `custom_phrase.txt` | ✅ 同步 | 自定义短语列表 |
| `lua/` 目录 | ✅ 同步 | 自定义 Lua 脚本 |
| `*.dict.yaml` | ✅ 同步 | 自制词典（若自己维护） |
| `*.userdb/` | ⚠️ 可选 | 用户词典 B+ 树，含输入历史和词频；文件较大且频繁变更 |
| `*.schema.yaml` | ⚠️ 可选 | 方案原始文件；通常由方案管理器安装，也可纳入同步 |
| `build/` | ❌ 不同步 | 编译产物（`.prism.bin`、`.table.bin` 等），每台设备部署时自动生成 |
| `*.bin` | ❌ 不同步 | 同上，`build/` 外散落的二进制文件 |

:::note
`build/` 是编译产物，与平台和 librime 版本绑定，跨设备复制会导致兼容性问题。同步源文件、各设备本地部署，是正确姿势。
:::

## 快速上手

    | 平台 | 前端 | 用户目录 |
    |------|------|---------|
    | macOS | Squirrel（鼠须管） | `~/Library/Rime/` |

  </Step>
  <Step title="选择同步方式">

    - **RIME 内置同步**：适合只同步用户词典、对 Git 不熟悉的用户
    - **云盘符号链接**：适合想要连续自动同步、不想手动操作的用户
    - **Git 工作流**：适合追求版本控制、回滚能力的用户（推荐）
  </Step>
  <Step title="配置同步并执行首次同步">
    按本文对应方案的说明完成配置，然后在第一台主力设备上执行一次同步或 push，确认文件已上传到中心位置（云盘或 Git 仓库）。
  </Step>
  <Step title="在其他设备拉取并部署">
    在每台其他设备上拉取配置（pull 或从云盘复制），然后触发「重新部署」，让 RIME 编译新配置。验证候选词、快捷键等行为与主力设备一致。
  </Step>
  <Step title="建立日常同步习惯">
    配置变更后及时同步：Git 用户在每次修改后 commit + push；云盘用户确认文件已上传后再切换到其他设备；内置同步用户在每台设备上定期点击「用户资料同步」。
  </Step>
</StepGuide>

## 方式一：RIME 内置同步

RIME 内置了一套用户词典同步机制，通过 `installation.yaml` 配置 `sync_dir` 字段，每次点击「用户资料同步」时，引擎会把本机的词典变更导出到该目录，并合并其他设备的变更。

### 配置 installation.yaml

在用户目录中新建或编辑 `installation.yaml`，填写以下字段：

<YamlPreview title="installation.yaml" caption="RIME 内置同步配置示例（macOS + iCloud Drive）">

```yaml
distribution_code_name: Squirrel
distribution_version: "1.0.2"
installation_id: "macbook_pro_home"
rime_version: 1.11.2
sync_dir: "/Users/username/Library/Mobile Documents/com~apple~CloudDocs/Rime-sync"
```

</YamlPreview>

各字段说明：

| 字段 | 说明 |
|------|------|
| `distribution_code_name` | 当前前端名称（`Squirrel` / `Weasel` / `ibus` / `fcitx5`）；区分不同前端产生的同步快照 |
| `installation_id` | 本机唯一标识，**每台设备必须不同**；同步目录下会以此名称创建子目录 |
| `sync_dir` | 同步目录的绝对路径；可以是云盘目录、NAS 挂载点或本地共享目录 |
| `rime_version` | librime 版本（自动生成，无需手动填写） |

:::warning
`installation_id` 必须在各设备上保持唯一。如果两台设备使用相同的 `installation_id`，它们的同步快照会互相覆盖，导致词典数据丢失。建议用机器名或「设备名\_用途」命名，如 `imac_home`、`thinkpad_work`。
:::

### 执行同步

配置完成后，在每台设备上触发同步：

- **macOS**：菜单栏输入法图标 → 「用户资料同步」
- **Windows**：托盘图标右键 → 「用户资料同步」
- **Linux（ibus-rime）**：`rime_api_console --sync`（或重启 ibus-daemon 后在日志中确认）
- **Android Trime**：App 内设置 → 「同步」

同步流程：
1. 将本机 `*.userdb/` 中的词频变更**导出**到 `sync_dir/<installation_id>/` 下的快照文件
2. 扫描 `sync_dir/` 下所有其他设备的快照，**合并**词典条目（取并集，权重取最大值）
3. 将合并结果**导入**本机词典

:::tip
内置同步主要针对**用户词典**（词频、个人词库）。`.custom.yaml`、Lua 脚本等配置文件不在内置同步范围内，需要另行同步。
:::

## 方式二：云存储同步

将 RIME 用户目录移动到云盘文件夹，然后在原位置创建符号链接。这样 RIME 读写配置时，实际上操作的是云盘目录，云盘客户端负责后台自动同步。

### macOS + iCloud Drive

```bash
# 将 Rime 目录移到 iCloud Drive
mv ~/Library/Rime \
   ~/Library/Mobile\ Documents/com~apple~CloudDocs/Rime

# 在原位置创建符号链接
ln -s \
   ~/Library/Mobile\ Documents/com~apple~CloudDocs/Rime \
   ~/Library/Rime
```

其他设备（同一 Apple ID）上执行相同操作，两台设备就会共享同一份 iCloud 上的配置目录。

### Windows + OneDrive

```powershell
# PowerShell（管理员权限）
$rimePath = "$env:APPDATA\Rime"
$onedrivePath = "$env:OneDrive\Rime"

# 将 Rime 目录移到 OneDrive
Move-Item $rimePath $onedrivePath

# 创建符号链接
New-Item -ItemType SymbolicLink -Path $rimePath -Target $onedrivePath
```

### Syncthing（跨平台开源方案）

[Syncthing](https://syncthing.net) 是 P2P 文件同步工具，无需依赖第三方云服务，适合在 Linux、Android、NAS 间同步：

1. 在所有设备安装 Syncthing
2. 将 RIME 用户目录（或其副本）添加为共享文件夹
3. 在 Syncthing Web UI 中配置忽略规则，排除编译产物：
   ```
   /build
   *.bin
   ```
4. 在各设备间建立信任关系，开始同步

:::warning
部分云盘（尤其是 iCloud 和 OneDrive）对频繁变更的 B+ 树文件（`*.userdb/`）会生成大量版本历史，占用较多云盘空间。若只想同步配置文件，可以在云盘的忽略列表中排除 `*.userdb/` 目录，用内置同步单独处理词典。
:::

## 方式三：Git 工作流

将 RIME 用户目录纳入 Git 版本控制，用私有仓库作为多设备间的同步中心。这是配置管理最干净的方式，完整保留修改历史，支持回滚。

### 初始化仓库

```bash
# macOS：进入用户目录
cd ~/Library/Rime/

# 初始化 Git 并推送到私有仓库
git init
git remote add origin git@github.com:yourname/rime-config.git
git add .
git commit -m "init: initial RIME config"
git push -u origin main
```

### 配置 .gitignore

```gitignore
# 编译产物（必须排除）
build/
*.prism.bin
*.table.bin
*.reverse.bin

# 用户词典（可选：若想共享学习词频则注释掉此行）
*.userdb/

# 系统文件
.DS_Store
Thumbs.db
```

### 日常工作流

```bash
# 修改配置后提交并推送
git add *.custom.yaml custom_phrase.txt lua/
git commit -m "feat: 启用自然码双拼"
git push

# 在另一台设备拉取最新配置
git pull
# 然后触发 RIME 重新部署
```

### 在新设备上快速安装

```bash
#!/bin/bash
# setup-rime.sh：在新设备上一键拉取配置

RIME_DIR="$HOME/Library/Rime"
REPO="git@github.com:yourname/rime-config.git"

# 备份已有配置
if [ -d "$RIME_DIR" ]; then
  mv "$RIME_DIR" "${RIME_DIR}.bak.$(date +%Y%m%d)"
fi

# 克隆配置仓库
git clone "$REPO" "$RIME_DIR"

echo "配置已就绪，请触发 RIME 重新部署。"
```

## 常见场景

**macOS + Windows 日常切换**

两台设备都装好 RIME，用 Git 同步配置，用内置同步合并词频。每天开始工作前在 macOS 上执行一次「用户资料同步」，Windows 上也执行一次，两边词频即可合并。

**台式 + 笔记本同组**

同一平台的两台设备最简单——用 Syncthing 或符号链接接入同一个云盘目录即可，所有文件实时同步，无需手动触发。

**桌面 + Trime（Android）同步**

Trime 使用 `/storage/emulated/0/rime/` 作为用户目录，可以通过以下方式同步：

1. 在手机上安装 Syncthing，将 `rime/` 目录加入同步
2. 或通过 USB 手动复制配置文件，然后在 Trime 中「重新部署」
3. 如果方案较大，建议只同步 `*.custom.yaml` 和 `custom_phrase.txt`，方案文件在手机上单独安装

**迁移到新机器**

新机器装好 RIME 前端后：

1. 从 Git 仓库 clone 配置：`git clone <repo> ~/Library/Rime/`（macOS）
2. 触发「重新部署」
3. 执行一次「用户资料同步」，从 `sync_dir` 中导入词典历史

<Details title="排错：同步后配置或用户词典丢失" level="advanced">

**symptom 1：同步后另一台设备的词频被覆盖清空**

最常见原因是两台设备使用了相同的 `installation_id`。RIME 内置同步以 `installation_id` 作为设备标识，相同 ID 的两台设备会互相覆盖快照，而不是合并。

修复：为每台设备分配唯一的 `installation_id`，删除 `sync_dir/` 下冲突的旧快照目录，重新同步。

**symptom 2：sync_dir 配置了但同步没有反应**

检查以下几点：

- `sync_dir` 路径是否存在且可写：`ls -la "/path/to/sync_dir"`
- 路径中是否有空格或特殊字符——iCloud 路径（`com~apple~CloudDocs`）在 `installation.yaml` 中需要写完整绝对路径，不能用 `~` 缩写
- 是否触发了正确的操作：「用户资料同步」（sync）而非「重新部署」（deploy）

**symptom 3：合并后出现大量重复候选词**

这通常发生在多台设备长期独立使用同一方案后首次合并。内置同步的合并算法取词条并集，短期内候选词数量会增加。这是正常现象，随着使用会逐渐收敛。

**symptom 4：Git pull 后部署失败**

新拉取的配置中可能引用了尚未安装的方案或词典文件。检查 `default.custom.yaml` 中 `schema_list` 里的每个方案，确认对应的 `.schema.yaml` 文件已在用户目录中。缺少的文件通过方案管理器安装后再部署。

**symptom 5：B+ 树文件损坏（`*.userdb/`）**

云盘在同步过程中如果发生中断，可能导致 B+ 树文件损坏（RIME 启动时报 `leveldb` 相关错误）。修复方法：

```bash
# 删除损坏的用户词典（词频数据会丢失，但配置不受影响）
rm -rf ~/Library/Rime/*.userdb/
# 重新部署，RIME 会创建新的空词典
```

</Details>

<Details title="原理：rime_sync 的合并算法" level="advanced">

RIME 内置同步使用 LevelDB 格式的 B+ 树存储用户词典（`*.userdb/`）。同步时的合并逻辑：

**用户词典合并（`*.userdb/`）**

1. 本机词典导出：把当前 `*.userdb/` 中所有条目序列化为 `sync_dir/<installation_id>/<schema>.userdb.txt` 文本快照
2. 多设备合并：扫描 `sync_dir/` 下所有设备的快照，对**同一词条**取权重最大值（`max(weight_A, weight_B)`），对各设备独有的词条取并集
3. 导入合并结果：将合并后的条目写回本机词典

这意味着：
- 词频只增不减——在 A 设备上学习的词在 B 设备上也会出现
- 如果在 A 上删除了一个词条，同步后可能从 B 的快照中恢复（因为取并集）
- 权重冲突时取最大值，不会因为某台设备的词频较低而压低整体词频

**配置文件合并**

`.custom.yaml` 等配置文件**没有自动合并机制**——内置同步不处理这些文件。如果两台设备的 `.custom.yaml` 同时修改了同一字段，最后写入 `sync_dir` 的那台设备会覆盖另一台（last-write-wins），内置同步不做三向合并。这是使用 Git 管理配置文件的主要原因。

</Details>

<Details title="跨前端同步的陷阱" level="advanced">

在 macOS（Squirrel）和 Windows（Weasel）之间同步时，有几个平台特定的配置键需要注意：

**`squirrel.yaml` / `weasel.yaml` 是平台专属文件**

这两个文件控制候选框外观、字体、App 特定规则（如在 Terminal 中自动切换到英文模式）。它们使用平台特定的语法：

- Squirrel 的 `app_options` 使用 macOS Bundle ID（如 `com.apple.Terminal`）
- Weasel 的 `app_options` 使用 Windows 进程名（如 `WindowsTerminal.exe`）

建议将平台专属配置分别放在 `squirrel.custom.yaml` 和 `weasel.custom.yaml` 中，而不是 `default.custom.yaml`，这样 Git 仓库中两份文件可以独立维护。

**字体名称差异**

macOS 和 Windows 上相同字体的名称可能不同（如「苹方」只在 macOS 上存在）。在 `default.custom.yaml` 中设置字体会导致另一平台回退到默认字体。同样建议在各自的平台配置文件中指定。

**换行符**

Windows 上用文本编辑器保存的 YAML 文件默认使用 CRLF 换行符。RIME 的 YAML 解析器能处理这个问题，但 Git 在 Windows 上默认会转换换行符（`core.autocrlf=true`）。建议在仓库根目录添加 `.gitattributes`：

```
*.yaml text eol=lf
*.lua  text eol=lf
*.txt  text eol=lf
```

确保仓库中所有文本文件统一使用 LF，避免 diff 噪声和潜在的解析问题。

</Details>

<Details title=".gitignore 应该排除什么" level="intermediate">

```gitignore
# ── 必须排除：编译产物 ──
build/
*.prism.bin
*.table.bin
*.reverse.bin
*.bin

# ── 建议排除：用户词典（按个人需求决定）──
# 保留此行：只同步配置，不共享词频
*.userdb/
# 注释掉：同时同步词频（仓库体积会变大，且频繁产生提交）
# *.userdb/

# ── 建议排除：RIME 安装信息 ──
# installation.yaml 包含 installation_id，各设备不同，不应共享
installation.yaml

# ── 操作系统文件 ──
.DS_Store
Thumbs.db
desktop.ini
```

**关于 `installation.yaml` 是否纳入 Git**：

该文件由 RIME 自动生成，包含 `installation_id`（设备唯一标识）和 `rime_version`（引擎版本）。由于各设备的 `installation_id` 必须不同，把它提交到 Git 会导致每台设备都需要在 pull 后手动修改，造成麻烦。建议排除该文件，每台设备自行维护。

</Details>
