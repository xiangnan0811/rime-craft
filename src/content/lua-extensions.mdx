# Lua 扩展

**Lua 扩展** 是 RIME 引擎可编程能力的统一入口。本模块将你看到的"特殊输入功能"、"输入统计"、"候选词注释增强"等能力集中管理，并允许你编写自定义 Lua 脚本扩展输入法行为。

## 这是什么

RIME 在处理输入时会依次调用一系列组件：按键处理（Processor）、分段（Segmentor）、翻译（Translator）、过滤（Filter）。Lua 让用户可以用脚本替代或增强其中任一环节。

- **特殊输入** 触发器（如 `/rq` 日期、`V` 计算器）本质上就是 Translator 类型的 Lua 脚本
- **超级注释**、**超级替换** 等增强功能是 Filter 类型的 Lua 脚本
- **超级处理器** 是 Processor 类型的 Lua 脚本

本模块的三个 Tab 对应三类使用方式：

- **特殊输入**：开关预设触发器、添加自定义触发器
- **内置功能增强**：调整万象方案自带的 Lua 功能参数
- **自定义脚本**：编写和管理你自己的 Lua 脚本

## 快速上手

:::tip
如果你只是想使用预设的日期、时间、计算器等功能，直接在「特殊输入」Tab 确认开关状态即可。
:::

  </Step>

## 配置项详解

### 特殊输入 · 预设触发器

| 触发码 | 功能 | 输出示例 |
|--------|------|---------|
| `/rq` | 当前日期 | 2026年4月10日 |
| `/sj` | 当前时间 | 14:30 |
| `/xq` | 当前星期 | 星期五 |
| `/nl` | 农历日期 | 三月十一 |
| `/jq` | 当前节气 | 清明 |
| `/jr` | 近期节日 | 清明节 |
| `/tt` | Unix 时间戳 | 1775808000 |
| `V` | 计算器 | V1+2 → 3 |
| `U` | Unicode | U4e07 → 万 |
| `/rtj` | 今日输入统计 | 今日输入 1234 字 |
| `/tj` | 累计输入统计 | 累计输入 56789 字 |

每个触发器可以单独开关，也可以改触发码。改触发码时注意避免和拼音编码冲突。

### 内置功能增强

| 子系统 | 作用 | 关键参数 |
|--------|------|---------|
| 超级注释 | 为候选词添加辅助码、拼音等注释 | 注释候选长度、纠错格式 |
| 超级处理器 | 增强键盘处理（退格保护、音节循环等） | 退格限制、音节循环、声调回落 |
| 超级替换 | 对候选词自动替换 | 链式替换、分隔符 |
| 用户预测 | 基于历史智能预测下一词 | 最大候选数、过期天数、激活天数 |
| 输入统计 | 记录输入字数/词数 | 启用开关 |

### 自定义脚本

每个脚本有三个属性：

- **文件名**：Lua 文件名（仅字母、数字、下划线、连字符），系统自动加 `.lua` 后缀
- **类型**：Translator / Filter / Processor
- **描述**：用于你自己识别的备注

:::note
Lua 脚本的编辑、触发器注册和 YAML patch 只是把组件挂到当前方案上。只有把对应的 `.lua` 文件一并放入用户目录并重新部署后，脚本逻辑才会真正生效。

如果你是从社区方案复制脚本，请同时检查它依赖的 `recognizer/patterns`、词表文件和额外配置项是否也已经迁移到自己的方案里。
:::

## 原理机制

一次输入的处理流程（简化示意）：

```
输入按键 → Processor → Segmentor → Translator → Filter → 候选词输出
```

当你在 schema 中注册一个 Lua 组件时，RIME 会将它插入到对应的组件链：

<YamlPreview title="xxx.custom.yaml（注册 Lua 组件的 patch 结构）" caption="lua_translator 会追加到 translator 链末尾">

```yaml
patch:
  engine/translators/+:
    - lua_translator@my_translator
  recognizer/patterns/my_translator: "^/hello$"
```

</YamlPreview>

- `engine/translators/+` 中的 `+` 表示"追加到现有数组"，而不是替换
- `recognizer/patterns/xxx` 定义了触发该翻译器的输入模式（正则）
- `lua_translator@my_translator` 中的 `my_translator` 必须对应 `lua/my_translator.lua` 文件，且文件返回的 Lua 函数名也应该是 `my_translator`

Filter 与 Translator 的注册方式几乎相同，区别在于挂载点和职责不同——Filter 不生成新候选词，而是对 Translator 已产生的候选词逐一处理：

<YamlPreview title="xxx.custom.yaml（注册 Filter 示例）" caption="lua_filter 追加到 filter 链，对已有候选词进行修改">

```yaml
patch:
  engine/filters/+:
    - lua_filter@my_comment_filter
```

</YamlPreview>

Filter 脚本接收上游候选词流，逐一处理后再 `yield` 出去。你可以在这里追加注释、跳过某些候选、调整顺序，但不能凭空产生新词（那是 Translator 的工作）。

### Translator / Filter / Processor 对比

| 类型 | 职责 | 典型场景 | 关键返回值 |
|------|------|---------|-----------|
| Translator | 生成新候选词 | 特殊输入、反查、自定义词表 | `yield(Candidate(...))` |
| Filter | 修改已有候选 | 追加注释、过滤词条、调整顺序 | `yield(cand)` |
| Processor | 拦截并处理按键事件 | 快捷键、状态切换、特殊模式 | `0` kNoop / `1` kAccepted / `2` kRejected |

三者可以在同一个方案中共存。通常的开发顺序是：先用 Translator 让功能可以触发，再用 Filter 做展示层美化，最后用 Processor 加快捷键入口。

同一类型的 Lua 组件也可以注册多个，它们会按 `engine/translators` 或 `engine/filters` 数组中的顺序依次执行，互不干扰。

## 完整示例：自定义 IP 查询触发器

目标：输入 `/ip` 时弹出候选词显示本机 IP 地址。

<StepGuide>
  <Step title="创建 Lua 脚本">
    进入「自定义脚本」Tab，点击「新建脚本 → Translator」。编辑器会用模板填充代码。将文件名改为 `ip_query.lua`，代码改为：

    ```lua
    local function ip_query(input, seg, env)
      if input == "/ip" then
        -- 示例：实际项目中可通过外部命令或 RIME API 获取 IP
        local ip = "192.168.1.100"
        yield(Candidate("word", seg.start, seg._end, ip, "本机 IP"))
      end
    end

    return ip_query
    ```
  </Step>
  <Step title="添加自定义触发器">
    切回「特殊输入」Tab，滚动到页面底部的「自定义触发器」区域，点击「+ 添加自定义触发器」：
    - 名称：IP 地址查询
    - 触发码：/ip
    - 关联脚本：ip_query.lua
  </Step>
  <Step title="导出并部署">
    保存配置并用「导出」按钮下载 schema 的 YAML patch 和 Lua 脚本文件。将它们放到 RIME 用户目录，重新部署。
  </Step>
  <Step title="验证">
    在任意应用输入 `/ip`，候选词列表应显示 "192.168.1.100"。
  </Step>
</StepGuide>

## 常见场景

- **办公场景**：日期、时间、星期是最常用的预设触发器。考虑关闭不常用的农历/节气以减少候选词干扰。
- **程序员场景**：时间戳 `/tt`、计算器 `V`、Unicode `U` 都非常实用。可以自定义触发器查询 IP、生成 UUID 等。
- **写作场景**：农历、节气、节日类触发器适合写古风、纪实类文章。
- **学习 RIME**：通过编写一个最简 Translator 脚本，能直观理解候选词从无到有的全流程。打印调试信息到 `rime.log` 后，每次输入都能观察到引擎的调用时机。
- **企业部署**：通过 Filter 类型的 Lua 脚本读取公司术语词表，对候选词追加缩写注释，或将特定产品名自动替换为规范写法，无需改动主词典。
- **实验性开发**：用 Lua 脚本验证新输入法思路时，可以在不修改主方案 schema 的前提下，通过 `custom.yaml` 的 `patch` 临时挂载实验性组件，随时摘除，不影响日常使用。

<Details title="进阶：RIME 引擎的完整组件链" level="advanced">

RIME 的数据流比上文简图更复杂。完整顺序是：

1. **Schema 加载**：编译 prism（词典前缀树）、symbols 等静态资源
2. **Processor 链**：按注册顺序调用每个处理器。返回 kAccepted 则后续处理器不再执行
3. **Segmentor 链**：将已输入的编码划分为音节或其它单位
4. **Translator 链**：每个翻译器独立产生候选词列表
5. **Filter 链**：顺序修改上一步的候选列表
6. 最终候选列表呈现给用户

Lua 组件可以插入到步骤 2、4、5 的任何位置。`engine/translators/+` 中的 `+` 是追加，更高级的位置控制使用 `@before`/`@after` 修饰符。

下面是一个 Filter 脚本的最小示例，展示候选词流是如何被遍历和修改的：

```lua
local function my_comment_filter(input, env)
  for cand in input:iter() do
    -- 可以在这里检查 cand.text、cand.type 等属性
    -- 修改 comment（候选词右侧的注释文字）
    cand.comment = "（自定义注释）"
    -- yield 将候选词传递给下一个 Filter 或最终输出
    yield(cand)
  end
end

return my_comment_filter
```

如果某个候选词不应出现，只需跳过 `yield(cand)` 这一行即可将它从列表中移除。

</Details>

<Details title="Lua 脚本的调试技巧" level="intermediate">

**用 `log.info()` 写入 rime.log**

RIME 的 Lua 环境提供了 `log.info()`、`log.warning()`、`log.error()` 三个函数。在脚本中插入日志后，重新部署并触发输入，即可在用户目录的 `rime.log` 中看到输出：

```lua
local function my_translator(input, seg, env)
  log.info("my_translator called, input=" .. input)
  -- ...
end
```

**分阶段开发**

推荐先写一个只返回硬编码候选词的最小版本，确认注册流程正确后，再逐步替换为真实逻辑。每次只改一处，遇到问题能快速定位。

**用预设 trigger 测试**

在 `recognizer/patterns` 中临时给你的脚本注册一个简单触发码（如 `/dbg`），测试通过后再改为正式触发条件。这样避免正式触发码的正则干扰调试。

**查阅 Lua API 参考**

RIME 的官方 Lua API 文档位于 [rime/librime-lua 的 wiki](https://github.com/hchunhui/librime-lua/wiki)，涵盖 `Candidate`、`Segment`、`env`、`yield` 等所有可用对象和方法。

</Details>

<Details title="排错指南：配置不生效怎么办" level="advanced">

**场景一：触发码不触发**

1. 检查「开关」是否开启
2. 检查触发码是否和其他输入冲突（比如 `/v` 可能撞到 `V` 计算器）
3. 检查 RIME 部署日志（用户目录下的 `rime.log`），搜索 `error` 或 Lua 相关报错
4. 确认 Lua 脚本文件已放到用户目录的 `lua/` 子目录
5. 确认 `xxx.custom.yaml` 中的 patch 已合并到正确位置

**场景二：Lua 脚本语法错误**

1. RIME 部署时会把错误写到日志。典型错误：
   - `attempt to call a nil value` — 函数名和 `return xxx` 的名字不一致
   - `unexpected symbol` — 语法错误，检查引号、括号匹配
2. 编辑器不做语义校验，建议在本地用 Lua 解释器先跑一遍（`lua -e 'dofile("my_translator.lua")'`）
3. 推荐配合 rime-ice 仓库的示例脚本比对你的代码

**场景三：自定义触发器 trigger 代码不起作用**

1. 检查 `recognizer/patterns/xxx` 的正则是否正确
2. 检查 schema 的其他 recognizer 是否抢先匹配了你的输入

</Details>

<Details title="注意事项与维护" level="advanced">

- **升级方案时**：更新万象拼音等方案时，你的自定义 `.lua` 文件不会被覆盖，但 `custom.yaml` 里的 patch 可能需要和新版本合并
- **多设备同步**：RIME 用户目录的 `lua/` 文件夹需要纳入同步范围。不同平台 RIME 用户目录路径不同，参考 [多设备同步](./multi-device-sync)
- **备份**：在对 Lua 脚本做较大修改前，建议用 Git 管理用户目录或至少复制一份备份
- **性能**：Lua 脚本每次输入都会被调用。避免在脚本中执行重量级操作（如同步 HTTP 请求）

</Details>

<Details title="性能注意事项" level="advanced">

Lua 脚本在每次按键时都可能被调用，Filter 类脚本还会对当前候选列表中的每一个候选词执行一次循环。以下几点有助于保持输入流畅：

- **避免重量级 I/O**：同步的 HTTP 请求、大文件读取会直接阻塞输入响应。如果需要读取外部数据，优先在脚本加载阶段（`init` 函数中）一次性读入内存，而不是每次调用时重复读取。
- **用 `env` 缓存跨调用状态**：RIME 在每次 schema 加载时会调用脚本的 `init(env)` 函数，可以把初始化数据存入 `env` 表，供后续调用复用，避免重复计算。

  ```lua
  local function init(env)
    -- 只在 schema 加载时执行一次
    env.word_set = load_word_list("my_terms.txt")
  end
  ```

- **字符串匹配选 `string.match`**：Lua 内置的 `string.match` 使用模式匹配，比引入外部 regex 库开销小得多。对于简单前缀判断，直接用 `string.sub(input, 1, 1) == "/"` 比正则更快。
- **参考万象拼音的 super_comment filter**：该脚本在处理大量候选词时做了显式的长度截断和 early-exit 优化，是研究性能友好型 Filter 写法的好案例。

</Details>
