# 反查与筛选

遇到不认识的字，不知道怎么读，拼音打不出来？反查（Reverse Lookup）就是为此设计的——通过字形、笔画、部首等方式找到字，并顺带学会它的读音。

## 这是什么

正常输入的方向是「知道读音 → 输入拼音 → 找到字」。反查则相反：「不知道读音 → 用其他方式描述字形 → 找到字，并看到它的拼音」。

反查解决三类场景：

- **生僻字**：只知道字怎么写，不会读，无法用拼音输入
- **忘记读音**：某字认识但声调记不准，普通输入候选太多
- **字形辅助**：用笔画或部件描述字的结构，精准定位

在万象拼音中，按下反查触发键（默认反引号 `` ` ``）即进入反查模式，候选词会同时显示汉字及其拼音，帮助你一边找字一边记住读法。

## 快速上手

<StepGuide>
  <Step title="在编辑器中找到反查模块">
    在 rime-craft 编辑器左侧导航找到「反查与筛选」模块。你会看到触发键、数据源、反查方式三个配置区。
  </Step>
  <Step title="确认触发键">
    默认触发键为反引号 `` ` ``（键盘左上角，数字 1 左边）。如需改为 `z` 或 `u`，在「反查触发键」输入框中修改即可。触发键应选一个你正常输入时不会用到的字符，避免冲突。
  </Step>
  <Step title="选择反查方式">
    在「反查方式」列表中开启所需的方法。对于初次使用的用户，推荐先开启**两分反查**和**笔画反查**：

    - **两分反查**：将字拆成两部分，输入各部分读音（最直觉）
    - **笔画反查**：用 `h/s/p/n/z` 五个字母代表横竖撇捺折（不需要知道读音）
  </Step>
  <Step title="保存并重新部署">
    点击右上角「保存」，然后触发重新部署：
    - macOS：菜单栏输入法图标 → 重新部署
    - Windows：小狼毫系统托盘 → 重新部署

    **必须部署**才能使配置生效，因为反查数据源需要重新编译索引。
  </Step>
  <Step title="实际使用">
    在任意输入框按下触发键，输入反查编码：

    - 笔画反查「中」：`` ` `` + `hspnz`（横竖撇捺折各一笔，按笔顺）→ 候选显示「中 zhōng」
    - 两分反查「明」：`` ` `` + `ri` + `yue` → 候选显示「明 míng」

    候选词右侧会显示拼音，帮助你记住读法。
  </Step>
</StepGuide>

## 配置项详解

### 反查触发键

触发键是进入反查模式的入口字符。RIME 通过 `recognizer/patterns/reverse_lookup` 正则来识别反查输入序列，触发键是该正则的前缀。

常见触发键选择：

| 触发键 | 优点 | 注意事项 |
|--------|------|---------|
| `` ` ``（反引号）| 键盘左上角，易触达，默认值 | 部分键盘布局可能不方便 |
| `z` | 普通字母键，容易记忆 | 若方案有 z 开头的拼音码需确认不冲突 |
| `u` | 小鹤双拼等方案中 u 无单独声母 | 仅适合双拼用户，全拼用户慎用 |
| `;`（分号）| 右手小指自然位置 | 部分方案用分号做其他功能 |

### 数据源

反查数据有两种来源，可以同时开启或只选其一：

| 数据源 | 说明 | 适用场景 |
|--------|------|---------|
| `aux`（词库注释） | 从词典文件的 aux 列提取反查信息，轻量，随词库自动更新 | 日常使用，偶尔反查 |
| `db`（独立数据库） | 使用独立的 `.reverse.bin` 反查数据库，数据更完整，覆盖更多生僻字和异体字 | 经常使用反查或需要查偏僻字 |

:::tip
如果你经常需要查生僻字或异体字，推荐同时开启两个数据源。`db` 数据库的字符覆盖比词库 aux 列更全面。
:::

### 反查方式

万象拼音支持 5 种反查方式，可单独开启或组合使用：

| 反查方式 | `enabledMethods` 值 | 使用方法 | 适用场景 |
|---------|---------------------|---------|---------|
| 两分反查 | `two_part` | 将字拆成左右/上下两部分，输入各部分读音 | 结构明显的合体字（最常用） |
| 多分反查 | `multi_part` | 将字拆成多个部分，逐一输入读音 | 复杂结构字如「赢、囊」 |
| 笔画反查 | `stroke` | 用 h/s/p/n/z 代表五种笔画，按笔顺输入 | 不知道读音也不会拆字时 |
| 声调反查 | `tone` | 输入拼音后附加声调数字（如 `ma3`）缩小范围 | 知道读音但同音字太多 |
| 辅助码反查 | `auxiliary` | 利用已学的辅助码编码反查 | 已学辅助码的用户快速上屏 |

笔画反查字母对照：

| 字母 | 笔画 | 代表汉字 |
|------|------|---------|
| `h` | 横（一） | 一、二、王 |
| `s` | 竖（丨） | 十、中、川 |
| `p` | 撇（丿） | 人、入、千 |
| `n` | 捺/点（丶） | 之、永、文 |
| `z` | 折（乛乙） | 了、乙、女 |

## 原理机制

### RIME 反查的实现方式

反查通过 `reverse_lookup_translator`（反查翻译器）实现，它作为独立的翻译器注册在 `engine/translators` 链中，与正常的拼音翻译器**并列运行**。

整个反查流程分四步：

1. **识别触发**：用户按下触发键，`recognizer/patterns/reverse_lookup` 的正则匹配到当前输入（如 `^` + `` ` `` + `[a-z]+$`），标记该 segment 为 `reverse_lookup` 类型
2. **路由到反查翻译器**：RIME 引擎将该 segment 交给 `reverse_lookup_translator` 处理，正常拼音翻译器跳过此 segment
3. **查询反查数据源**：翻译器根据配置从 aux 列或 `.reverse.bin` 数据库中查找编码匹配的汉字列表
4. **返回带注音候选**：候选词附带 `comment`（注释）字段，显示该字的拼音，帮助用户确认找到了正确的字

### 反查翻译器与正常翻译器的共存

反查翻译器和拼音翻译器不会相互干扰，因为 RIME 在分词（segmentation）阶段就已经区分了普通输入和反查输入。`recognizer` 组件负责识别特殊前缀，一旦某段输入被标记为 `reverse_lookup`，就只有对应的翻译器响应它。

这意味着你可以在同一个方案中同时使用：
- 正常拼音输入（走拼音翻译器）
- 反查模式（走反查翻译器）

两者独立工作，切换无缝。

## 完整示例

<YamlPreview title="wanxiang.custom.yaml" caption="启用笔画反查，触发键为 z，数据源取自独立反查数据库">

```yaml
patch:
  engine/translators/+:
    - reverse_lookup_translator
  recognizer/patterns/reverse_lookup: "^z[a-z]*$"
  reverse_lookup:
    prefix: "z"
    suffix: ";"
    tips: "〔笔画〕"
    dictionary: stroke
    preedit_format:
      - "xlit/hspnz/横竖撇捺折/"
```

</YamlPreview>

配置说明：

- `prefix`：触发键，与 `recognizer` 正则中的前缀字符保持一致
- `suffix`：可选，输入该字符后结束反查（类似确认键）
- `tips`：候选列表顶部显示的提示文字，提醒用户当前处于反查模式
- `dictionary`：反查使用的字典名（`stroke` 为 RIME 内置笔画字典）
- `preedit_format`：将显示在输入预览区的编码做人类可读转换（`h` → 横）

## 常见场景

### 生僻字：用笔画反查不需要知道读音

遇到完全不认识的字，只能一笔一笔描述它：

```
触发键（`） + 按笔顺输入 hspnz
例：查「永」字（横撇捺撇撇捺）→ `hpnppn
候选显示：永 yǒng
```

笔画反查不需要知道读音，只需要能目测出笔顺，是最通用的反查方式。

### 忘记声调：声调反查缩小候选

知道字的读音但声调记不清，同音字太多时：

```
触发键 + 拼音 + 声调数字（1-4，0 表示轻声）
例：`ma3 → 候选只显示第三声的「马、码、骂」等
```

配合两分或笔画可进一步缩小范围。

### 辅助码反查：移动端或新设备快速上屏

已经学习了辅助码的用户，在不熟悉的设备上也能用辅助码快速定字：

```
触发键 + 拼音 + 辅助码
直接利用已有的辅助码知识，无需切换思路
```

### 同音字消歧：拼音 + 笔画组合

「jī」有「机、鸡、基、积」等大量同音字，加笔画可精确定位：

```
两分反查：输入 "木" 旁的读音 → 候选范围大幅缩小
笔画反查：描述字的前几笔 → 精确命中
```

<Details title="排错：反查触发后无候选或反查模式未激活" level="advanced">

按以下顺序排查：

**1. 确认 recognizer 正则与触发键一致**

`reverse_lookup_translator` 的 `prefix` 字段必须与 `recognizer/patterns/reverse_lookup` 正则中的前缀字符完全一致。常见错误：

```yaml
# 错误：recognizer 用反引号，但 prefix 写成 z
recognizer/patterns/reverse_lookup: "^`[a-z]*$"
reverse_lookup:
  prefix: "z"    # ❌ 不一致，反查永远不会触发

# 正确：保持一致
recognizer/patterns/reverse_lookup: "^z[a-z]*$"
reverse_lookup:
  prefix: "z"    # ✅
```

**2. 确认反查字典已加载**

反查使用的 `dictionary`（如 `stroke`）必须是系统中存在的字典文件。检查 RIME 用户目录下是否有 `stroke.dict.yaml`，或系统共享目录中是否有该文件。如果字典不存在，反查翻译器会静默失败（无候选）。

**3. 检查 build 目录的 .reverse.bin 文件**

反查数据库在重新部署时生成，存储在 `build/<schema_id>.reverse.bin`。如果该文件不存在或时间戳早于上次配置修改，说明部署未成功完成，查看 `rime.log` 的错误信息。

**4. 确认 reverse_lookup_translator 已注册**

`engine/translators` 列表中必须包含 `reverse_lookup_translator`。如果使用 `+` 追加，确认追加写法正确：

```yaml
patch:
  engine/translators/+:
    - reverse_lookup_translator   # ✅ 追加
```

不要用 `engine/translators:` 覆盖整个列表，除非你列出了所有原本的翻译器。

**5. 触发键与其他功能冲突**

如果触发键（如 `` ` ``）被其他 `recognizer` 模式先捕获，反查模式可能不会激活。检查 `recognizer/patterns` 下有没有优先级更高的正则匹配了同样前缀。

</Details>

<Details title="原理：reverse_lookup_translator 在翻译器链中的优先级" level="advanced">

RIME 的翻译器链按 `engine/translators` 列表顺序执行，但反查翻译器的触发方式决定了它不会与普通翻译器竞争。

**分段（segmentation）阶段**决定了一切：

- 普通输入 → `Segmentor` 标记为 `raw` 或 `abc` 类型 → 拼音翻译器处理
- 反查输入 → `Recognizer` 匹配 `reverse_lookup` 模式 → 标记为 `reverse_lookup` 类型 → 只有反查翻译器处理

各翻译器在 `translate()` 方法中检查 segment 类型，不匹配就直接返回空。因此反查翻译器注册在列表中的位置（前或后）不影响行为——重要的是 segment 类型已经在分段阶段确定好了。

**多反查翻译器**：如果你需要支持多种反查触发（例如 `` ` `` 触发笔画，`z` 触发拼音注音），可以注册多个反查翻译器，每个对应不同的 `recognizer` 模式和 `dictionary`。

</Details>

<Details title="自定义反查数据源：创建 .reverse.bin 或使用词典 aux 列" level="advanced">

**方式 A：在词典中添加 aux 列**

RIME 词典文件（`.dict.yaml`）支持在编码列之后追加 aux 注释列。反查时 `dataSource: aux` 会从该列提取信息：

```yaml
# 词典文件片段（wanxiang.dict.yaml）
# 字/词  编码     aux 列（可用于反查）
明       ming     ri-yue
赢       ying     wang-kou-yue-bei-fan
```

**方式 B：使用独立的 stroke 字典**

RIME 内置 `stroke.dict.yaml`，收录了汉字的笔画编码。直接在反查配置中指定：

```yaml
reverse_lookup:
  dictionary: stroke
```

这是最常用的笔画反查配置，无需自行准备数据。

**方式 C：构建自定义反查数据库**

如果你有专门的字形或部件数据，可以创建自定义词典并在反查配置中引用。部署时 RIME 会自动编译对应的 `.reverse.bin` 文件。

字典格式要求：每行一个条目，`字形编码<Tab>汉字`，部署后生成的 `.reverse.bin` 支持双向查询（编码→字，字→编码）。

</Details>

<Details title="反查 vs 辅助码：两种不同的字形补充机制" level="intermediate">

反查和辅助码都与字形有关，但用途和触发时机完全不同：

| 特性 | 反查（Reverse Lookup） | 辅助码（Auxiliary Code） |
|------|----------------------|------------------------|
| **触发时机** | 正式输入之前，专门进入「找字模式」 | 在正常拼音输入过程中追加，用于缩小候选 |
| **适用场景** | 完全不知道读音，需要通过字形找到字 | 知道读音，同音字太多需要定字 |
| **输入流程** | 触发键 → 字形编码 → 找到字及其读音 | 拼音 → 字形辅助码 → 精确候选 |
| **学习后** | 反查到读音后，下次可直接用拼音 | 是日常输入的一部分，持续使用 |
| **配置位置** | `reverse_lookup` 字段 | `auxiliary_code` 字段 |

**什么时候用哪个**：

- 不认识的字 → 用**反查**找到它，记住读音
- 认识但同音字多（如「jī」）→ 用**辅助码**在正常输入中精确定字
- 想系统提高输入效率 → 学辅助码；偶尔遇到生僻字 → 用反查

两者可以同时启用，互不冲突。

</Details>
