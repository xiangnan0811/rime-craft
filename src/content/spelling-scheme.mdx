# 拼写方案

拼写方案定义了「按键序列 → 拼音音节」的映射规则。全拼下字母直接对应拼音；双拼下两个键就能表达一个完整音节——声母键 + 韵母键。万象拼音内置 7 种方案，一键切换，无需额外安装文件。

## 这是什么

输入拼音的两种主流方式：

**全拼**（full_pinyin）：音节按标准拼音逐字母拼出，按键数不固定。「装」= `zhuang`（6 键），「你」= `ni`（2 键）。优点是零学习成本；缺点是长音节击键偏多。

**双拼**：每个音节固定压缩为 2 键（声母键 + 韵母键），通过一套键位映射实现。以小鹤双拼为例：「装」= `vl`（2 键），「你」= `ni`（2 键）。学习成本约 1–2 周，熟练后每个音节都是 2 击，整体输入效率提升约 20–30%。

:::tip
双拼的核心是「声母表 + 韵母表」两张映射表。记住这两张表之后，就能无障碍输入所有音节。大多数学习者的经验是：前三天最慢，一周后追上全拼速度，两周后明显更快。
:::

### 万象支持的 7 种拼写方案

| 方案值 | 名称 | 设计思路 | 适合人群 |
|--------|------|---------|---------|
| `full_pinyin` | 全拼 | 标准拼音，无额外映射 | 不想学双拼的用户 |
| `flypy` | 小鹤双拼 | 左右手负担均衡，韵母键位连续 | 首选新学双拼方案 |
| `zrm` | 自然码双拼 | 历史最久，韵母键以自然联想为设计原则 | 自然码老用户 |
| `mspy` | 微软双拼 | 微软拼音内置方案 | 从微软拼音迁移 |
| `sogou` | 搜狗双拼 | 搜狗输入法默认双拼 | 从搜狗迁移 |
| `abc` | 智能ABC双拼 | 经典老方案，声韵母键位各有特点 | 智能ABC老用户 |
| `ziguang` | 紫光双拼 | 紫光/华宇拼音方案 | 从紫光迁移 |

各方案的主要差异在于**韵母的键位分布**，声母键位大体一致。如果没有历史包袱，推荐选择**小鹤双拼**——社区活跃、学习资料丰富、键位均衡。

## 快速上手

  <Step title="在编辑器中找到拼写方案模块">
    在 rime-craft 编辑器左侧导航找到「拼写方案」模块。当前激活的方案会高亮显示。
  </Step>
  <Step title="选择目标方案">

  </Step>
  <Step title="保存并重新部署">
    点击右上角「保存」，然后触发「重新部署」：
    - macOS：菜单栏输入法图标 → 重新部署
    - Windows：小狼毫系统托盘 → 重新部署
    - Linux：`ibus-daemon -drx` 或对应命令

    **切换方案后必须部署**，因为 RIME 需要重新编译 prism 索引。
  </Step>
  <Step title="测试输入">
    在任意输入框尝试双拼。以小鹤双拼为例：
    - 「我」→ `wo`（声母 w，韵母 o，共 2 键）
    - 「是」→ `ui`（声母 u 代表 sh，韵母 i，共 2 键）
    - 「装」→ `vl`（声母 v 代表 zh，韵母 l 代表 uang，共 2 键）
  </Step>
  <Step title="打印键位对照表">
    切换方案成功后，建议打印或保存一张该方案的键位对照图放在桌上，前一周随时参考。互联网上搜索「小鹤双拼键位图」即可找到高清版本。
  </Step>

## 配置项详解

### 方案值与 YAML 字段

切换拼写方案对应编辑方案配置文件中的 `speller/spelling_scheme` 字段：

```yaml
patch:
  speller/spelling_scheme: flypy    # 可选: full_pinyin, flypy, zrm, mspy, sogou, abc, ziguang
```

当该字段指定为双拼方案时，RIME 会加载内置的对应 algebra 规则集，将双拼键序列展开为标准拼音音节后查词。

### 主流双拼键位对比

以韵母 `iang`（亮/想/强）和 `uang`（装/王/光）为例，各方案的映射键位差异：

| 韵母 | 小鹤 flypy | 自然码 zrm | 微软 mspy | 搜狗 sogou |
|------|-----------|-----------|---------|-----------|
| `iang` | `l` | `d` | `l` | `l` |
| `uang` | `l` | `l` | `d` | `d` |
| `ing` | `k` | `k` | `k` | `k` |
| `uan` | `r` | `r` | `r` | `r` |
| `ui`（uei）| `v` | `v` | `v` | `v` |
| `un`（uen）| `y` | `y` | `n` | `p` |

:::note
声母映射在各方案间更为统一：`zh → v`（多数方案）、`ch → i`（小鹤）或其他键、`sh → u`（小鹤）。选方案前可以重点对比自己高频字涉及的韵母键位。
:::

## 原理机制

### RIME 如何实现双拼

RIME 的双拼不是独立的输入法逻辑，而是通过 `speller/algebra`（拼写运算列表）将用户输入的双拼键序列**展开还原**为标准拼音音节，然后用同一套全拼词典查词。

整个过程分三步：

1. 用户按键，RIME 收到原始字母序列，如 `vl`
2. `algebra` 规则按顺序执行，将 `vl` 展开为 `zhuang`
3. 展开后的标准拼音去词典查词，返回候选

这意味着双拼和全拼**共享同一个词库**——切换拼写方案不影响词频数据，用户词典完全兼容。

### algebra 中的 xform 与 abbrev

双拼规则主要使用两种指令：

| 指令 | 作用 | 双拼中的角色 |
|------|------|---------|
| `xform` | **替换**编码（原编码消失） | 将双拼键序列变换为全拼音节 |
| `abbrev` | 允许缩略，原编码保留 | 支持首字母缩写（可选） |
| `derive` | 派生额外编码，原编码保留 | 模糊音（见[模糊音规则](./fuzzy-pinyin)） |

双拼使用 `xform` 而非 `derive`，因为双拼键位本身就是映射目标，不需要保留原始键序列作为另一种合法输入。例如小鹤双拼中 `v` 键专门代表 `zh`，没有必要同时接受 `v` 字母本身作为拼音输入。

### prism 前缀树的编译

`algebra` 规则在**重新部署**时被编译成 prism（前缀索引树），存储在 `build/<schema_id>.prism.bin`。prism 将词典中所有词条按照变换后的编码重建索引。这是为什么：

- 切换方案后必须重新部署——部署 = 重新编译 prism
- 运行时无性能损耗——RIME 查词时直接读 prism，不再执行正则

## 完整示例

<YamlPreview title="wanxiang.custom.yaml" caption="切换为小鹤双拼（flypy）">

```yaml
patch:
  speller/spelling_scheme: flypy
```

</YamlPreview>

如果需要手动写出完整的小鹤双拼 algebra 规则（用于自定义方案或调试），核心规则如下：

<YamlPreview title="double_pinyin_flypy.schema.yaml（speller 片段）" caption="小鹤双拼的声母与韵母映射规则">

```yaml
speller:
  alphabet: zyxwvutsrqponmlkjihgfedcba
  delimiter: " '"
  algebra:
    # ── 声母映射 ──────────────────────────────
    - xform/^([jqxy])u$/$1v/       # jqxy 后的 u 实为 ü
    - xform/^zh/v/                  # zh → v
    - xform/^ch/i/                  # ch → i
    - xform/^sh/u/                  # sh → u
    # ── 韵母映射 ──────────────────────────────
    - xform/iang$/l/                # iang → l
    - xform/uang$/l/                # uang → l（与 iang 共键）
    - xform/iong$/s/                # iong → s
    - xform/uan$/r/                 # uan  → r
    - xform/iao$/n/                 # iao  → n
    - xform/ing$/k/                 # ing  → k
    - xform/ang$/h/                 # ang  → h
    - xform/eng$/g/                 # eng  → g
    - xform/ong$/s/                 # ong  → s（与 iong 共键）
    - xform/ian$/m/                 # ian  → m
    - xform/iao$/n/                 # iao  → n
    - xform/ie$/p/                  # ie   → p
    - xform/ue$/t/                  # ue   → t
    - xform/ui$/v/                  # ui   → v
    - xform/ua$/x/                  # ua   → x
    - xform/ia$/x/                  # ia   → x（与 ua 共键）
    - xform/ao$/c/                  # ao   → c
    - xform/an$/j/                  # an   → j
    - xform/en$/f/                  # en   → f
    - xform/in$/b/                  # in   → b
    - xform/un$/y/                  # un   → y
    - xform/ou$/z/                  # ou   → z
    - xform/ei$/w/                  # ei   → w
    - xform/ai$/d/                  # ai   → d
    - xform/er$/q/                  # er   → q（独立韵母）
    - xform/iu$/q/                  # iu   → q（与 er 共键）
    # ── 首字母缩写（可选）──────────────────
    - abbrev/^([a-z]).+$/$1/
```

</YamlPreview>

:::note
`iang` 和 `uang` 共用 `l` 键、`iong` 和 `ong` 共用 `s` 键——这是双拼的合并设计。RIME 能正确区分它们，因为声母不同时，整个音节的 xform 结果也不同（如 `l` + `l` 表示 `liang`，`v` + `l` 表示 `zhuang`）。
:::

## 常见场景

### 初学者：保持全拼起步

如果你刚开始使用 RIME，建议先用全拼熟悉词库和各项功能，再考虑切换双拼：

```yaml
patch:
  speller/spelling_scheme: full_pinyin
```

全拼是默认值，不需要显式设置——此示例仅说明字段的写法。

### 高频输入者：迁移到小鹤双拼

对于每天打字量大的用户，小鹤双拼是投入产出比最高的选择：

```yaml
patch:
  speller/spelling_scheme: flypy
```

:::tip
迁移策略：在周末切换，前两天不要追求速度，专注于查对照表把每个字打完整。大脑建立肌肉记忆通常需要 7–14 天，中途不要切回全拼——反复切换只会延长适应期。
:::

### 从搜狗或微软拼音迁移

如果你在其他输入法中已经习惯了某种双拼键位，直接切换到对应方案，零适应成本：

```yaml
patch:
  speller/spelling_scheme: mspy    # 微软双拼用户
  # 或
  # speller/spelling_scheme: sogou  # 搜狗双拼用户
```

### 双拼 + 辅助码（最高效组合）

双拼固定 2 键表达音节，再追加 1–2 个字形码（辅助码）精确定字，最多 4 键即可无歧义输入一个汉字：

```yaml
patch:
  speller/spelling_scheme: flypy
  auxiliary_code/scheme: hexing       # 小鹤形辅助码，与小鹤双拼搭配
  auxiliary_code/trigger_mode: direct # 直接辅助，最高效
```

### 混用：双拼 + 模糊音

双拼和模糊音可以同时使用，但需注意规则叠加的顺序：

```yaml
patch:
  speller/spelling_scheme: flypy
  speller/algebra/+:
    - derive/^([zcs])h/$1/          # 平翘舌模糊（追加在双拼规则之后）
    - derive/^([zcs])([^h])/$1h$2/
```

:::warning
在双拼模式下追加模糊音规则时，必须使用 `speller/algebra/+`（带加号追加），**不能**用 `speller/algebra:`（替换整个列表）。替换整个列表会清空双拼的 xform 规则，导致双拼失效。
:::

<Details title="排错：双拼切换后某些音节无法输入" level="advanced">

按以下顺序排查：

1. **确认已重新部署**：切换方案后必须重新部署才能重建 prism。macOS 菜单栏输入法图标 → 重新部署；Windows 小狼毫托盘 → 重新部署。单纯保存 custom.yaml 不够。

2. **检查 patch 路径是否正确**：切换拼写方案的字段路径是 `speller/spelling_scheme`，不是 `speller/algebra`。常见误写：

   ```yaml
   # 错误：字段名拼写有误
   patch:
     speller/spelling_schema: flypy    # ❌ schema → scheme
   
   # 正确
   patch:
     speller/spelling_scheme: flypy    # ✅
   ```

3. **查看 build 目录时间戳**：打开 RIME 用户目录下的 `build/` 文件夹，查看 `<schema_id>.prism.bin` 的修改时间。如果时间早于你最后一次部署，说明部署未成功完成——检查 `rime.log` 的错误信息。

4. **custom.yaml 覆盖了错误的方案**：万象拼音（`wanxiang`）的拼写方案写在 `wanxiang.custom.yaml`，而不是 `default.custom.yaml`。如果你修改的是 `default.custom.yaml`，字段不会生效。

5. **algebra 规则被意外覆盖**：如果你在 custom.yaml 中同时有 `speller/algebra:` 和 `speller/spelling_scheme:`，前者可能清空了双拼所需的规则。检查是否误用了完整路径覆盖。

</Details>

<Details title="原理：xform vs abbrev 在双拼中的职责分工" level="advanced">

双拼方案的 algebra 中混用了 `xform` 和 `abbrev`，两者职责不同：

**`xform`（变换）**

`xform/<匹配>/<替换>/` 会**替换**匹配到的编码，原始编码消失。双拼中所有「键位 → 拼音」的映射都用 `xform`：

```
输入: vl
xform/^zh/v/ 的反向：vl 中 v → zh
xform/iang$/l/ 的反向：l → iang
最终展开: zhuang
```

注意 algebra 是从词典侧向键位侧做变换（把拼音变成键序列），RIME 在查词时将用户输入与变换后的编码匹配。

**`abbrev`（缩略）**

`abbrev/<匹配>/<替换>/` 与 `derive` 类似，但产生的编码在整句输入模式下会降低优先级，避免单字母把句子候选挤掉。双拼方案中典型用途是首字母缩写：

```yaml
- abbrev/^([a-z]).+$/$1/    # 允许只输入首字母
```

开启后输入 `v` 单字母时，会出现 zh 开头的字，但整句候选的优先级高于这些缩写候选。

**核心区别**：模糊音用 `derive`（双向保留），双拼键位映射用 `xform`（单向替换），缩略用 `abbrev`（保留但降权）。

</Details>

<Details title="自定义双拼方案：从零定义键位映射" level="advanced">

如果现有方案都不满足需求（例如你有一套自己设计的键位），可以从零编写 algebra 规则。

**基本结构**

一套完整的双拼 algebra 由两部分组成：

1. **声母表**：将特殊双拼声母键还原为标准声母
2. **韵母表**：将韵母键还原为标准韵母

```yaml
speller:
  algebra:
    # 声母表：把双拼声母键还原为标准声母
    - xform/^zh/[你分配的键]/
    - xform/^ch/[你分配的键]/
    - xform/^sh/[你分配的键]/
    
    # 韵母表：把标准韵母变换为双拼键
    - xform/iang$/[你分配的键]/
    - xform/uang$/[你分配的键]/
    # ... 覆盖全部约 35 个韵母
```

**设计要点**

- 每个键只能对应一组声母或一组韵母（或一组共键韵母），不能有歧义
- `zh/ch/sh` 三个双声母必须映射到非字母开头的键（通常用 `v/i/u` 或其他不冲突的键）
- 韵母合并（共键）时，声母 + 韵母键的组合必须仍是唯一的

**验证方法**

写完规则后，重新部署并系统地测试每个韵母对应音节的输入。可以写一个测试词表，覆盖所有 400+ 个普通话音节。若某个音节无法输入，检查对应的 xform 规则是否覆盖了该韵母，或者是否存在规则顺序冲突。

</Details>

<Details title="各双拼方案学习曲线对比" level="intermediate">

选择双拼方案的三个维度：**键位记忆难度**、**上手速度**、**高频键位是否顺手**。

| 方案 | 记忆难度 | 社区资源 | 键位均衡性 | 推荐场景 |
|------|---------|---------|---------|---------|
| 小鹤 flypy | 中 | 最丰富 | 优 | 从零开始学习双拼 |
| 自然码 zrm | 中 | 丰富 | 良 | 已有自然码基础 |
| 微软 mspy | 低（如有基础）| 较少 | 中 | 从微软拼音迁移 |
| 搜狗 sogou | 低（如有基础）| 较少 | 中 | 从搜狗拼音迁移 |
| 智能ABC abc | 高 | 极少 | 差 | 仅老用户保留习惯 |
| 紫光 ziguang | 高 | 极少 | 中 | 仅老用户保留习惯 |

**学习周期参考**（基于社区反馈）：

- 有意识练习：前 3 天最慢（约为全拼速度的 30–50%）
- 第 1 周末：基本能流畅输入（约为全拼速度的 70–80%）
- 第 2 周末：速度追平甚至超越全拼
- 1 个月后：进入肌肉记忆阶段，无需有意识回忆键位

</Details>
