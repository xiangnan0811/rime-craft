# Typography + Docs Token Unification

**Date:** 2026-04-16
**Status:** Approved for plan
**Brainstorming thread:** carried in the April 16 dark-mode review conversation

## Background

The 2026-04 dark-mode remediation landed five commits that replaced hard-coded
`bg-gray-*` / `text-gray-*` classes with semantic design tokens
(`bg-muted`, `text-muted-foreground`, `bg-background`, `text-foreground`, …)
across the home page, editor, schema detail, wizard, gallery, compare,
dialogs, and simulator surfaces. Two follow-ups were deferred because they
required more than a mechanical replace:

1. **Adopt `@tailwindcss/typography`** for MDX content rendering, which is
   currently handled by a ~140-line hand-rolled override module
   (`src/components/shared/mdx-components.tsx`).
2. **Unify the docs subroute** (seven files under `src/app/docs/`, the
   always-dark `CodeBlock` / `YamlPreview` wrappers, and the `rehype-pretty-code`
   configuration) onto the shared CSS tokens so docs no longer has its own
   `slate-*` palette.

This spec captures the chosen shape for both, the migration path, and the
risks identified during brainstorming.

## Goals

- Collapse duplicated styling logic: `.prose` becomes the single source of
  truth for plain HTML element rendering inside MDX.
- Docs routes share the same tokens as the rest of the app, so a future
  `--background` / `--muted` / `--border` tweak automatically re-skins docs.
- Code blocks become theme-aware: light on light-mode, dark on dark-mode,
  syntax-highlighted appropriately in each.
- Keep the business logic that currently lives inside `mdx-components.tsx`
  (router-aware `<a>`, directive-dispatched `<div>` callouts, overflow-wrapped
  `<table>`) untouched.

## Non-goals

- Pixel-perfect visual fidelity with today's hand-rolled typography. We
  accept prose-sm defaults; minor spacing / sizing differences are tolerated.
- Any visual-regression harness (Playwright / screenshot diffing). Testing
  stays manual; see §6.
- Rewriting existing MDX tutorials. The 17 files under `src/content/` render
  unchanged content through the new pipeline.
- Touching the editor-form tokens. The P0–P3 dark-mode work is in.

## Chosen architecture

### High-level

```
┌───────────────────── before ──────────────────────┐
│  MDX ─► mdx-components.tsx (13 HTML overrides +   │
│        5 business components) ─► hard-coded       │
│        gray/slate with paired dark: variants      │
│  Docs UI: gray-* / slate-* twin palette           │
│  CodeBlock / YamlPreview: always-dark shell       │
│  rehype-pretty-code: single `one-dark-pro` theme  │
└───────────────────────────────────────────────────┘
                           │
                           ▼
┌───────────────────── after ───────────────────────┐
│  MDX ─► mdx-components.tsx (5 business            │
│        components + a / div / table business      │
│        shells) ─► prose at the container          │
│  Docs UI: muted / accent / background tokens      │
│  CodeBlock / YamlPreview: theme-aware shells      │
│  rehype-pretty-code: { light: ..., dark: ... }    │
└───────────────────────────────────────────────────┘
```

### Core principles

1. **Prose owns pure-style tags.** `h1 h2 h3 p ul ol li blockquote hr strong`
   (and optionally `table` infrastructure) are deleted from
   `mdx-components.tsx`. `.prose` on the MDX container provides the baseline.
2. **Tokens are the single dark / light source of truth.** Delete every
   `gray-*` ↔ `slate-*` pair in docs. The `.dark` class on `<html>` swaps CSS
   variable values; Tailwind classes consume `hsl(var(--foo))`.
3. **Code blocks are first-class themed citizens.** `rehype-pretty-code`
   emits both light and dark syntax spans; shiki's `keepBackground: true`
   paints the matching theme background inside `<pre>`. The wrapper (border,
   title bar, copy button) uses `bg-card` / `border-border` /
   `text-muted-foreground`.

### `mdx-components.tsx` after refactor

**Deleted overrides** (prose handles them):
```
h1  h2  h3  p  ul  ol  li  blockquote  hr  strong  thead  th  td
```

**Retained overrides** (business logic, not pure styling):
- `a` — distinguishes `./slug` relative tutorial links (which switch
  `activeModule` inside the editor or navigate via Router to `/docs/:slug`)
  from absolute internal paths (Router Link) and external links.
- `div` — reads `data-directive` to dispatch `Callout` for `:::tip` /
  `:::warning` / `:::note` / `:::caution` directives generated by
  `remark-directive-rehype`.
- `table` — wraps in an `overflow-x-auto` container so long tables don't
  blow out the mobile viewport (prose does not do this by default).
- `pre` — the existing `CodeBlock.Pre` (copy button, title reading).
- `code` — the existing `CodeBlock.InlineCode`.

**Heading slugging.** `h1 h2 h3` currently compute an `id` via an in-file
`slugify()` helper so docs anchor links work. After the refactor, the
`rehype-slug` plugin runs in `vite.config.ts`'s rehype chain so the MDX AST
gets `id` attributes before it reaches prose. The in-file helper is deleted.

**Final shape.** The file shrinks from ~140 lines to ~50: 5 named business
components plus three HTML shells (`a`, `div`, `table`).

### `index.css` — prose token bridge

```css
@layer base {
  .prose {
    --tw-prose-body: hsl(var(--foreground) / 0.85);
    --tw-prose-headings: hsl(var(--foreground));
    --tw-prose-links: hsl(217 91% 60%);
    --tw-prose-bold: hsl(var(--foreground));
    --tw-prose-quotes: hsl(var(--muted-foreground));
    --tw-prose-quote-borders: hsl(var(--border));
    --tw-prose-bullets: hsl(var(--muted-foreground));
    --tw-prose-hr: hsl(var(--border));
    --tw-prose-code: hsl(var(--foreground));
    --tw-prose-th-borders: hsl(var(--border));
    --tw-prose-td-borders: hsl(var(--border));
  }
  .dark .prose {
    --tw-prose-body: hsl(var(--foreground) / 0.9);
    --tw-prose-headings: hsl(var(--foreground));
    --tw-prose-links: hsl(217 91% 70%);
    --tw-prose-bold: hsl(var(--foreground));
    --tw-prose-quotes: hsl(var(--muted-foreground));
    --tw-prose-quote-borders: hsl(var(--border));
    --tw-prose-bullets: hsl(var(--muted-foreground));
    --tw-prose-hr: hsl(var(--border));
    --tw-prose-code: hsl(var(--foreground));
    --tw-prose-th-borders: hsl(var(--border));
    --tw-prose-td-borders: hsl(var(--border));
  }
}
```

Consequence: MDX containers use `className="prose prose-sm max-w-none"` alone.
We do **not** add `dark:prose-invert` — the token bridge already handles
dark mode. If a future contributor wraps MDX with `dark:prose-invert`, prose's
default dark palette will override ours; document this in a comment in
`index.css`.

### `vite.config.ts` — shiki dual theme

```ts
[rehypePrettyCode, {
  theme: { light: 'github-light', dark: 'one-dark-pro' },
  keepBackground: true,
}]
```

Plus `rehype-slug` added to the rehype chain *before* `rehype-pretty-code`.

### CodeBlock / YamlPreview — token-wrapped

- `CodeBlock.tsx`: outer `<div>` → `bg-card border-border`; title bar →
  `bg-muted`; title / copy-button text → `text-muted-foreground` /
  `hover:text-foreground`. The `<pre>` itself is unchanged — shiki paints its
  own background inside (`keepBackground: true`).
- `YamlPreview.tsx`: outer `<div>` → `bg-card border-border`; title bar →
  `bg-muted`. The diff highlights (`bg-green-500/10`, `bg-red-500/10`) remain
  because semi-transparent tints work in both modes.
- The `InlineCode` wrapper was already switched to `bg-muted text-foreground`
  in commit `82283a9`; no change.

### Docs route UI — token mapping

Seven files: `DocsLayout.tsx`, `DocsPage.tsx`, `DocsToc.tsx`,
`DocsBreadcrumb.tsx`, `DocsPagination.tsx`, `DocsSearch.tsx`,
`DocsMobileSidebar.tsx`.

Map by the **light-mode** class (the darker partner drops out with the
`dark:`-paired variant it shipped with):

| Old light-mode class      | Replacement            |
| ------------------------- | ---------------------- |
| `bg-gray-50`              | `bg-muted/30`          |
| `bg-gray-100`             | `bg-accent`            |
| `bg-white` (popovers)     | `bg-background`        |
| `text-gray-400`           | `text-muted-foreground` |
| `text-gray-500`           | `text-muted-foreground` |
| `text-gray-600`           | `text-foreground/80`   |
| `text-gray-700`           | `text-foreground/90`   |
| `text-gray-900`           | `text-foreground`      |
| `border-gray-200`         | `border-border`        |

Delete the paired `dark:bg-slate-*`, `dark:text-slate-*`,
`dark:border-slate-*` from the same className entirely — the token handles
both modes.

**Preserved** (informational colors stay informational, keep their
`dark:`-paired variants):
- `bg-blue-50 dark:bg-blue-950/30` on the active docs nav item.
- `border-l-2 border-blue-500` active-route stripe.
- `text-blue-500` hover hint on pagination chevrons.

## Migration path

Four steps, each independently committable / revertible. CI must stay green
between steps.

### Step 1 — Foundation (no visible change)

- `npm install --save-dev @tailwindcss/typography rehype-slug`
- `tailwind.config.ts`: add `require('@tailwindcss/typography')` to `plugins`.
- `index.css`: add the `.prose` / `.dark .prose` token bridge from §"index.css".
- `vite.config.ts`: change rehype-pretty-code to dual theme, add rehype-slug
  *before* rehype-pretty-code in the rehype chain.

Nothing consumes `.prose` yet, and the shiki dual-theme's light branch stays
invisible without the `.dark` class → this commit is a no-op visually.

**Exit criteria:** `npm run lint && npm run typecheck && npm test` all green;
manual spot-check of `/editor` and `/docs` shows no visible diff; check
`dist/assets/index-*.css` size delta < 2 KB gzipped.

### Step 2 — Theme-aware code blocks (first visible diff)

- CodeBlock.tsx: outer wrapper + title bar → tokens per §"CodeBlock".
- YamlPreview.tsx: outer wrapper + title bar → tokens per §"YamlPreview".

Exit criteria:

- github-light's keyword/string/comment colors have adequate contrast on
  `bg-card` (i.e., pure white in light mode).
- Copy button and title text remain legible against light bg.
- Dark mode unchanged (shiki auto-selects one-dark-pro via `.dark`).
- If github-light is too washed out, fall back to `min-light`,
  `catppuccin-latte`, or `vitesse-light` (all bundled with shiki).

### Step 3 — Wire prose, delete redundant mdx overrides

- `TutorialPanel.tsx` and `ImmersiveView.tsx`: re-add
  `className="prose prose-sm max-w-none"` on the MDX container. No
  `dark:prose-invert`.
- `mdx-components.tsx`: delete `h1 h2 h3 p ul ol li blockquote hr strong thead
  th td` entries. Delete the `slugify()` helper and its import. Keep `a`,
  `div`, `table`, `pre`, `code`, and the 5 business component exports.

Exit criteria:

- Docs anchors (e.g. `/docs/schema-manager#输入方案管理`) scroll to the right
  heading — rehype-slug is generating ids.
- `:::tip` / `:::warning` / `:::note` / `:::caution` still render as Callouts.
- `./slug` relative links inside `/editor` still switch `activeModule`;
  inside `/docs`, they navigate via Router.
- A volunteer reader (or self after 30-minute break) reads two tutorials and
  reports any "looks weird" moment. Tracked in PR description.

### Step 4 — Docs route UI tokens

- 7 files per §"Docs route UI — token mapping". **One file per commit** so a
  regression can be bisected cleanly.
- Suggested order: `DocsLayout` → `DocsToc` → `DocsBreadcrumb` →
  `DocsPagination` → `DocsSearch` → `DocsMobileSidebar` → `DocsPage`.
- No logic changes, only className rewrites.

Exit criteria per file:

- Light/dark both show correct contrast and no missing backgrounds.
- Active-route indicator still visible in both modes.

## Risks & mitigations

**R1 — prose defaults feel off vs. today's hand-rolled typography** (high
probability, medium impact). Mitigation: after Step 3, have a fresh reader
review 2–3 tutorials. Rollback is cheap — inject `fontSize` / `lineHeight` /
margin overrides via `tailwind.config.ts`'s `typography.DEFAULT.css`.

**R2 — github-light contrast inadequate** (medium, medium). Mitigation:
Step 2 preview locally before committing. Alternatives are in-bundle:
`min-light`, `catppuccin-latte`, `vitesse-light`.

**R3 — rehype-slug's github-slugger differs from existing `slugify()`** (high,
low). `github-slugger` preserves Chinese and dedupes collisions with
`-1` / `-2`; current helper lowercases and replaces non-word chars. Internal
MDX has no `#anchor` references (verify with
`grep -r '](#' src/content/`), so the blast radius is limited to external
links to specific headings. Mitigation: ship an announcement; fallback is
passing a custom slugger to rehype-slug (~10 lines) that mirrors the old
behavior.

**R4 — "terminal look" code blocks aesthetically preferred** (low, subjective
but impactful if true). Mitigation: Step 2 is the smallest commit — three
className rewrites — so it reverts independently if user feedback prefers
always-dark. Escape hatch: support `data-theme="always-dark"` on a
per-block basis in a future iteration, not in this spec.

**R5 — a `--tw-prose-*` variable gets missed in the token bridge** (low,
high). Mitigation: Step 1 lands the full bridge before any consumer. A
missed variable presents as an obvious color mismatch under dark mode, not
subtle.

**R6 — `@tailwindcss/typography` CSS bundle size** (low, low). Typography
plugin generates classes on demand via JIT; prose adds ~15 KB (~3 KB gzip).
We're well under budget but flag at Step 1's exit criteria.

## Testing

Manual only. No visual-regression harness in this spec.

Rationale:
- Affected page count < 15 (7 docs files, TutorialPanel, ImmersiveView, 17
  MDX outputs rendered through the same pipeline).
- Light + dark manual walkthrough < 10 minutes.
- Introducing Playwright / `@axe-core` is its own P4 investment and should
  not ride on the coattails of this work.

The existing 417-test suite guards `mdx-components.tsx`'s business logic
indirectly (YamlPreview tests, Callout tests, StepGuide tests, a handful of
MDX-rendering integration tests). Before Step 3 lands, audit whether any
test specifically asserts rendered HTML structure of removed elements (e.g.
`<h2>` with an `id` attribute) and update or delete those assertions to
track the new rehype-slug output.

## Open questions

None at spec time. Revisit if any Step's exit criteria fail.

## Out of scope / future work

- Snapshot or screenshot regression tests (Playwright / axe-core).
- `data-theme="always-dark"` escape hatch for specific code blocks.
- Moving rehype chain configuration out of `vite.config.ts` into a named
  module — cosmetic; do it if the chain grows past 4 plugins.
- Applying the token migration to `features/wizard/WizardPage.tsx`'s step
  indicator (already done in commit `d295140`).
